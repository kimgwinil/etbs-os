# 이제너두 전사 CRM OS PRD 초안

## 1. 문서 목적

이 문서는 이제너두 전사 CRM OS의 초기 제품 요구사항을 정의하고, MVP 범위를 인당 생산성 및 마진 개선 기여도 기준으로 우선순위화하기 위한 팀장 초안이다.

본 문서는 개발 확정안이 아니라 A1~A9 전문 에이전트에게 배분할 요구사항 기준선이며, 예산, 외부계약, 개인정보 처리범위, 아키텍처 확정은 PM 김권일 승인 후 진행한다.

인당 생산성/마진 기여: 요구사항을 먼저 수익성 기준으로 정렬해 낮은 ROI 개발과 중복 업무 자동화를 줄인다.

## 2. 회사 컨텍스트

- 회사: 이제너두
- 사업 성격: 선택적복지 B2E 플랫폼
- 사업 구조: 공급사/입점사, 플랫폼, 고객사, 임직원으로 구성된 3면 B2B2C 운영
- 운영 규모: 고객사 약 2,800개, 임직원 약 260만 명 이상
- 핵심 경영상 문제: 매출 대비 인원 과다, 영업이익률 3%대
- 최우선 판단 기준: 인당 생산성 및 마진 개선
- 필수 규제/통제: ISMS, 개인정보 및 민감정보 보호, 외감 회계 대응

인당 생산성/마진 기여: 회사의 구조적 병목을 제품 목표에 직접 연결해 기능 우선순위가 현장 편의가 아니라 이익률 개선으로 수렴하게 한다.

## 3. 제품 비전

이제너두 전사 CRM OS는 고객사, 공급사, 임직원, 계약, 포인트, 정산, CS, 자동심사, 외부 연동을 하나의 운영 콘솔과 데이터 기준으로 통합해 비개발자도 회사 운영을 관리할 수 있는 업무 OS를 지향한다.

초기 MVP는 모든 업무를 한 번에 대체하지 않고, 반복 처리량이 많고 인력 투입이 큰 운영 업무부터 통합한다.

인당 생산성/마진 기여: 업무 OS화로 담당자별 엑셀, 메신저, 수기 확인, 별도 관리자 화면 왕복 시간을 줄이고 동일 인력의 처리량을 높인다.

## 4. 핵심 사용자

| 사용자 | 주요 목표 | 주요 문제 |
|---|---|---|
| 경영진/PM | 수익성, 생산성, 리스크를 한 화면에서 판단 | 고객/공급/정산/CS 데이터가 분산되어 의사결정 속도가 느림 |
| 영업/AM | 고객사 상태, 계약, 이슈, 갱신 가능성을 관리 | 고객 히스토리와 수익성 정보가 분리됨 |
| 운영 담당자 | 포인트, 정산, 신청/심사, CS를 빠르게 처리 | 반복 확인과 예외 처리에 인력 소모가 큼 |
| 재무/정산 담당자 | 외감 대응 가능한 정산/회계 근거 확보 | 거래·포인트·정산 근거 추적이 복잡함 |
| 보안/개인정보 담당자 | 개인정보 흐름과 접근 통제 확인 | 민감정보 접근과 감사로그 관리 부담 |
| 공급사/입점사 담당자 | 상품/정산/계약 상태 확인 | 플랫폼 운영팀 문의 의존도가 높음 |

인당 생산성/마진 기여: 사용자별 병목을 분리해 자동화와 화면 통합이 실제 인력 절감 포인트에 연결되게 한다.

## 5. MVP 목표

MVP의 목표는 2주 내 실행 가능한 기반 스펙과 첫 구현 범위를 만들고, 이후 담당 에이전트가 독립적으로 설계/개발/검증할 수 있도록 모듈 경계와 인수조건을 확정하는 것이다.

### MVP 성공 기준

- 운영자가 고객사/공급사/임직원 관련 핵심 상태를 단일 콘솔에서 조회할 수 있다.
- 반복 운영 업무의 접수, 배정, 처리, 이력 관리 기준이 정의된다.
- 포인트, 정산, 결제, 온누리, 베네카페 연동의 어댑터 경계가 정의된다.
- 개인정보, 감사로그, 권한, 외감 대응 요구가 제품 요구사항에 포함된다.
- 각 스토리는 목적, 입력, 출력, 인수조건, 의존성, 담당, KPI 영향을 가진다.

인당 생산성/마진 기여: 2주 MVP를 "완성형 시스템"이 아니라 고반복 업무의 처리량과 수익성 가시화를 검증하는 단위로 제한해 낭비를 줄인다.

## 6. MVP 모듈 우선순위 제안

우선순위는 다음 기준으로 산정한다.

- P0: 인력 투입이 크고, 매출/마진/리스크에 직접 연결되며, 다른 모듈의 기반이 되는 기능
- P1: MVP 운영 효율을 높이지만 P0 기반 이후 정확도가 올라가는 기능
- P2: 중요하나 초기에는 수동 보조 또는 후속 단계로 운영 가능한 기능

| 우선순위 | 모듈 | 핵심 범위 | 담당 에이전트 | KPI 영향 |
|---|---|---|---|---|
| P0 | CRM Core | 고객사, 공급사, 임직원, 계약, 담당자, 활동 이력의 기준 데이터 | A1, A2, A4 | 중복 조회 감소, 고객/공급 운영 단위 통합 |
| P0 | Operations Console | 운영 업무 접수, 배정, 상태, SLA, 일괄 처리 화면 | A2, A3, A8 | 담당자 1인당 처리 건수 증가, 평균 처리시간 감소 |
| P0 | Security & Audit Baseline | RBAC, 테넌트 격리, 개인정보 접근로그, 감사로그 | A1, A2, A7, A9 | ISMS/외감 리스크 감소, 재작업 비용 감소 |
| P0 | Profitability Dashboard | 고객사/공급사별 매출, 원가, 마진, 운영 투입량 지표 | A3, A4 | 저마진 고객/업무 식별, 인력 배치 최적화 |
| P1 | Settlement & Point Ops | 포인트 지급/차감/정산 상태, 예외 큐, 회계 근거 추적 | A2, A4, A5, A6, A7 | 정산 오류/문의 감소, 외감 대응 시간 감소 |
| P1 | Integration Hub | 베네카페, 결제, 온누리, 외부 API 연동 어댑터 기준 | A1, A2, A6, A9 | 연동 장애 대응 시간 감소, 재처리 자동화 |
| P1 | Automation/RPA Workbench | 의료비, 학자금, 포인트, 정산 자동심사/자동처리 후보 | A5, A7, A8 | 자동화율 증가, 수작업 심사 시간 감소 |
| P2 | Supplier Portal | 공급사 상품/정산/계약 상태 셀프 조회 | A3, A6, A7 | 운영 문의 감소, 공급사 대응 효율 증가 |
| P2 | Customer Success Workspace | 갱신, 이탈 위험, VOC, 과업 관리 | A3, A4, A5 | 유지율 개선, AM 업무 표준화 |

인당 생산성/마진 기여: P0를 기준 데이터, 운영 처리량, 보안/감사, 수익성 가시화로 제한해 높은 인건비 업무와 리스크 비용을 먼저 줄인다.

## 7. MVP 범위

### 포함

- 고객사, 공급사, 임직원, 계약, 담당자, 활동 이력의 최소 데이터 모델
- 운영 업무 큐: 접수, 배정, 처리, 보류, 완료, 반려
- 운영 콘솔의 검색, 필터, 상태 변경, 일괄 처리 기준
- 고객사/공급사별 수익성 대시보드의 지표 정의
- 포인트/정산/결제/온누리/베네카페 연동을 위한 어댑터 스펙 초안
- RBAC, 테넌트 격리, 개인정보 접근로그, 감사로그 요구사항
- 각 모듈별 인수조건과 첫 스펙 작성 기준

### 제외

- 전체 ERP 대체
- 모든 외부 연동의 즉시 구현
- 공급사/고객사 포털 전체 기능
- AI 자동 의사결정의 무검토 운영
- 확정되지 않은 개인정보 처리범위 기반 구현
- 예산 또는 외부계약이 필요한 상용 솔루션 도입 확정

인당 생산성/마진 기여: 범위를 제한해 초기 비용을 통제하고 가장 큰 수작업 병목부터 검증한다.

## 8. 주요 에픽

### E1. 기준 데이터 통합

- 고객사, 공급사, 임직원, 계약, 담당자, 활동 이력을 통합한다.
- 모든 운영 업무가 동일한 엔티티 ID를 참조하도록 한다.

인당 생산성/마진 기여: 데이터 재입력과 담당자별 별도 관리 비용을 줄인다.

### E2. 운영 업무 큐 및 일괄 처리

- 반복 업무를 접수, 배정, 처리, 보류, 완료, 반려 상태로 표준화한다.
- 필터, 담당자 배정, SLA, 일괄 상태 변경 기준을 정의한다.

인당 생산성/마진 기여: 운영자 1명이 처리할 수 있는 건수를 높이고 업무 누락을 줄인다.

### E3. 수익성 및 생산성 대시보드

- 고객사/공급사/업무유형별 매출, 원가, 마진, 처리시간, 처리건수를 보여준다.
- 저마진 또는 고투입 업무를 경영진이 식별할 수 있게 한다.

인당 생산성/마진 기여: 인력 배치와 고객/공급사 운영 정책을 마진 기준으로 조정할 수 있다.

### E4. 포인트/정산/연동 기준화

- 포인트, 정산, 결제, 온누리, 베네카페 연동의 상태와 실패 처리 기준을 정의한다.
- 멱등성, 재시도, 폴백, 수동 보정 큐를 요구사항에 포함한다.

인당 생산성/마진 기여: 장애와 예외 처리에 쓰는 고비용 운영 시간을 줄인다.

### E5. 보안/컴플라이언스 내재화

- 개인정보 접근, 권한, 감사로그, 테넌트 격리, 외감 증적을 기본 요구로 포함한다.
- 민감정보 처리범위는 PM 승인 전 확정하지 않는다.

인당 생산성/마진 기여: 사후 보완과 감사 대응 비용을 줄이고 규제 리스크로 인한 손실을 예방한다.

## 9. 비기능 요구사항

- 대용량: 260만 명 이상 임직원 데이터를 고려한 조회/검색/권한 설계
- 멀티테넌트: 고객사별 데이터 격리와 역할 기반 접근 제어
- 감사 가능성: 주요 변경, 승인, 정산, 개인정보 접근 로그 보존
- 연동 안정성: 멱등 처리, 재시도, 실패 큐, 수동 보정 경로
- 운영 효율: 검색, 필터, 일괄 처리, CSV/Excel 반입·반출 정책 검토
- 보안: 개인정보 최소 수집, 암호화, 접근권한 분리, 로그 모니터링
- 확장성: Windows 및 iOS 업무 운영을 고려한 웹 우선 반응형 또는 PWA 검토

인당 생산성/마진 기여: 성능, 권한, 감사, 연동 실패 대응을 초기 요구에 포함해 운영 확대 시 인력 증가를 억제한다.

## 10. 주요 가정

- 현재 레거시 시스템, 베네카페, 결제, 온누리 연동 방식의 상세 API 문서는 아직 제공되지 않았다.
- "Windows 또는 iOS" 운영은 네이티브 앱 확정이 아니라 웹 기반 업무 접근성 요구로 해석한다.
- 개인정보 및 민감정보의 정확한 항목, 보관기간, 위탁/재위탁 범위는 PM 승인 대상이다.
- 예산, 상용 SaaS 도입, 외부 SI/보안 컨설팅 계약은 아직 확정하지 않는다.

인당 생산성/마진 기여: 불확실성을 명시해 잘못된 전제 기반 개발비 지출을 막는다.

인당 생산성/마진 기여: 주요 실패 원인을 선제 분리해 재작업과 과잉 구현을 줄인다.

## 12. STEP1 결론

MVP의 1차 우선순위는 다음 네 가지 P0 모듈이다.

1. CRM Core
2. Operations Console
3. Security & Audit Baseline
4. Profitability Dashboard

이 네 모듈은 이후 STEP2의 ARCHITECTURE, DATA_MODEL, 기술스택 권고의 기준 입력으로 사용한다.

인당 생산성/마진 기여: 기준 데이터, 처리량, 규제 리스크, 수익성 판단을 동시에 잡아야 운영 인력 증가 없이 회사 규모에 맞는 관리 체계를 만들 수 있다.

3. 개인정보/민감정보 항목과 외부 연동 상세는 STEP2에서 확정하지 않고, 별도 승인 게이트로 분리해도 되는가?
