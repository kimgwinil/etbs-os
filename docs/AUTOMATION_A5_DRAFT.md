# A5 Automation/RPA Workbench 초안

## 1. 문서 목적

이 문서는 이제너두 전사 CRM OS의 P1 Automation/RPA Workbench 범위를 정의하고, P0 Operations Console의 운영 업무 큐와 연결해 자동화 후보 업무의 우선순위, 자동 처리 기준, 사람 검토 기준, 반려/보류/재처리 기준을 정리한다.

본 문서는 개발 확정안이 아니며, 예산, 외부계약, 개인정보 처리범위, 민감정보 사용 범위, 최종 아키텍처는 PM 김권일 승인 전 확정하지 않는다.

인당 생산성/마진 기여: 반복 승인과 수기 분류 업무를 처리량·예외율 기준으로 정렬해 운영자 1인당 처리건수를 높이고 저마진 운영 투입을 줄인다.

## 2. PRD 연결 범위

Automation/RPA Workbench는 PRD의 P1 모듈이지만, 단독 화면이 아니라 P0 Operations Console의 접수, 배정, 처리, 보류, 완료, 반려 상태를 자동화 엔진과 예외 큐가 확장하는 방식으로 연결한다.

| 연결 대상 | A5 역할 | 결정 | 인당 생산성/마진 기여 |
|---|---|---|---|
| P0 Operations Console | 자동화 대상 업무를 동일한 운영 큐에 등록 | 자동 처리 결과도 운영 콘솔 이력에 남긴다 | 자동화와 수동 처리를 한 화면에서 관리해 담당자 전환 비용을 줄인다 |
| P0 Security & Audit Baseline | 자동화 판단, 사람 승인, 반려 사유의 감사로그 요구 | 자동화 판단 근거를 이벤트 단위로 남긴다 | 오류 추적과 감사 대응 시간을 줄여 재작업 비용을 낮춘다 |
| P0 Profitability Dashboard | 업무유형별 자동화율, 평균 처리시간, 예외율 제공 | 자동화 KPI를 고객사/업무유형별로 집계한다 | 저마진 고객사와 고투입 업무를 식별해 인력 배치를 개선한다 |
| P1 Settlement & Point Ops | 포인트/정산 자동 검증 및 예외 큐 연결 | 금액·잔액·중복·상태 불일치 건은 사람 검토로 보낸다 | 정산 오류와 반복 문의를 줄여 고비용 확인 시간을 낮춘다 |

## 3. 주요 가정

- 가정: 레거시 총무대행, 의료비, 학자금, 포인트, 정산, CS 시스템의 상세 데이터 구조와 API는 아직 제공되지 않았다.
- 가정: 자동화 1차 범위는 "완전 자동 의사결정"이 아니라 규칙 기반 자동 분류, 자동 승인 후보 선별, 예외 큐 라우팅으로 시작한다.
- 가정: 첨부 영수증, 진단서, 재학증명서, 가족관계증명서 등 민감정보 또는 고위험 개인정보가 포함될 수 있으나, 실제 수집 항목과 보관기간은 PM 김권일 승인 전 확정하지 않는다.
- 가정: 외부 RPA 솔루션 또는 OCR/AI 심사 솔루션 도입은 예산과 외부계약 승인 전 확정하지 않는다.

인당 생산성/마진 기여: 불확실한 개인정보와 외부 솔루션 범위를 가정으로 분리해 과잉 개발과 승인 지연 비용을 줄인다.

## 4. 자동화 후보 우선순위 기준

자동화 후보는 다음 6개 항목을 1~5점으로 평가해 우선순위를 산정한다.

| 기준 | 설명 | 높은 점수 의미 |
|---|---|---|
| 반복량 | 월간 처리 건수와 시즌성 피크 | 인력 투입 절감 여지가 큼 |
| 규칙 명확도 | 입력값, 증빙, 승인 조건의 정형화 수준 | 자동 승인 가능성이 큼 |
| 평균 처리시간 | 담당자 1건 처리에 걸리는 시간 | 자동화 시 절감 시간이 큼 |
| 예외율 | 사람 검토가 필요한 비율 | 낮을수록 1차 자동화 적합 |
| 리스크 | 금전, 개인정보, 고객사 신뢰 영향 | 낮을수록 무인 처리 적합 |
| 연동 준비도 | 원천 데이터와 결과 반영 경로의 명확도 | 빠른 MVP 검증 가능 |

결정: 1차 MVP에서는 "반복량 높음 + 규칙 명확 + 금전 리스크 통제 가능" 업무를 먼저 자동화하고, 의료/학자금처럼 민감정보 가능성이 높은 업무는 자동 승인보다 자동 분류와 사람 검토 라우팅을 우선한다.

인당 생산성/마진 기여: 자동화 성공 가능성이 높은 업무부터 처리해 초기 개발비 대비 처리시간 절감 효과를 빠르게 만든다.

## 5. 자동화 후보 우선순위

| 순위 | 업무 후보 | 자동화 형태 | 우선순위 사유 | 주요 예외 | KPI 영향 |
|---|---|---|---|---|---|
| 1 | CS 분류 및 반복 승인 업무 | 자동 분류, 자동 배정, 템플릿 응답 후보, 중복 문의 묶음 | 입력 패턴이 반복되고 P0 운영 큐와 즉시 연결 가능 | VIP 고객사, 법무/개인정보, 환불/정산 연계 문의 | 평균 1차 분류시간 감소, 담당자 1인당 처리건수 증가 |
| 2 | 포인트 지급/차감 운영 | 규칙 검증, 중복 체크, 자동 승인 후보, 예외 큐 | 금액·고객사·대상자·사유 기준으로 정형 검증 가능 | 잔액 부족, 중복 요청, 대량 업로드 오류, 권한 불일치 | 포인트 처리시간 감소, 오류율 감소 |
| 3 | 정산 대사 및 재처리 | 자동 대사, 차이 검출, 재처리 후보 생성 | 반복 검증이 많고 외감 증적 가치가 큼 | 금액 차이, 상태 불일치, 공급사 이의제기, 기간 경계 | 정산 예외 탐지시간 감소, 외감 대응 시간 감소 |
| 4 | 총무대행 의료비 접수 | 자동 접수 검증, 증빙 누락 탐지, 사람 검토 라우팅 | 처리량은 크지만 민감정보 가능성이 높아 검토 큐 우선 | 진료/질병 정보, 가족관계, 중복 청구, 한도 초과 | 검토 전 정리시간 감소, 반려 사유 표준화 |
| 5 | 학자금 신청 접수 | 자동 접수 검증, 재학/기간/한도 체크, 사람 검토 라우팅 | 시즌성 피크가 높고 조건 검증 가능 | 가족관계, 재학증빙, 학기/기간 불일치, 중복 신청 | 피크 시즌 처리시간 감소, 보완 요청 감소 |

결정: CS 분류, 포인트, 정산 대사를 1차 자동화 후보로 두고 의료비와 학자금은 민감정보 처리범위 승인 전 자동 승인 대상에서 제외한다.

인당 생산성/마진 기여: 고반복·저위험 업무에서 자동화율을 먼저 올리고, 고위험 업무는 검토 준비시간을 줄이는 방식으로 리스크 비용을 통제한다.

## 6. 업무별 요구사항

### 6.1 CS 분류 및 반복 승인 업무

| 항목 | 내용 |
|---|---|
| 목적 | 반복 문의를 업무유형, 고객사, 긴급도, 담당팀으로 자동 분류하고 Operations Console 큐에 자동 배정한다. |
| 입력 | 문의 채널, 제목/본문, 고객사 ID, 임직원 ID 또는 요청자 식별자, 첨부 여부, 과거 문의 이력, SLA 정책 |
| 출력 | 분류 카테고리, 우선순위, 담당 큐, 자동 응답 후보, 중복 문의 그룹, 사람 검토 필요 여부 |
| 인수조건 | 동일 문의가 중복 등록되면 하나의 그룹으로 묶인다. 개인정보/법무/정산 키워드는 자동 완료하지 않고 사람 검토 큐로 이동한다. 자동 분류 결과는 운영 콘솔에서 수정 가능하다. |
| 의존성 | Operations Console 업무 큐, CRM Core 고객사/담당자 데이터, Security & Audit 접근로그, CS 원천 채널 연동 |
| 담당 | A5 주관, A2 운영 콘솔 연동, A7 개인정보/감사 기준, A8 현장 운영 검증 |
| KPI 영향 | 자동화율, 평균 1차 분류시간, 담당자 1인당 처리건수, SLA 초과율 |

결정: CS는 자동 완료보다 자동 분류와 담당 큐 배정을 MVP 1차 목표로 한다.

인당 생산성/마진 기여: 문의를 읽고 배정하는 시간을 줄여 운영자가 실제 해결 업무에 쓰는 시간을 늘린다.

### 6.2 포인트 지급/차감 운영

| 항목 | 내용 |
|---|---|
| 목적 | 포인트 지급/차감 요청의 대상자, 금액, 사유, 중복, 잔액, 승인권한을 자동 검증하고 승인 가능 건과 예외 건을 분리한다. |
| 입력 | 고객사 ID, 임직원 ID, 포인트 유형, 지급/차감 금액, 사유 코드, 요청자, 승인자, 원천 파일 또는 API 요청, 기존 포인트 이력 |
| 출력 | 자동 승인 후보, 사람 검토 큐, 반려 후보, 포인트 처리 이벤트, 감사로그 |
| 인수조건 | 동일 고객사·임직원·금액·사유·기간의 중복 요청을 탐지한다. 잔액 부족과 권한 불일치는 자동 처리하지 않는다. 자동 승인 후보도 운영 콘솔에서 사전/사후 샘플링 검토가 가능하다. |
| 의존성 | Settlement & Point Ops, CRM Core 임직원/고객사 데이터, Security & Audit, 외부 포인트 원장 또는 레거시 연동 |
| 담당 | A5 주관, A2 업무 큐, A6 연동 어댑터, A7 감사/권한, A8 운영 검증 |
| KPI 영향 | 자동화율, 평균 처리시간, 포인트 오류율, 재처리율, 담당자 1인당 처리건수 |

결정: 포인트 자동 처리는 고객사별 한도, 승인권한, 원장 반영 멱등성이 확인된 범위에서만 허용한다.

인당 생산성/마진 기여: 반복 검증과 대량 업로드 확인 시간을 줄이되 금전 오류로 인한 보정 비용을 방지한다.

### 6.3 정산 대사 및 재처리

| 항목 | 내용 |
|---|---|
| 목적 | 정산 대상 거래, 공급사 청구, 포인트/결제 상태를 자동 대사하고 차이 발생 건을 예외 큐로 보낸다. |
| 입력 | 거래 ID, 공급사 ID, 고객사 ID, 정산 기간, 청구 금액, 지급 금액, 수수료/원가 항목, 결제/포인트 상태, 이전 재처리 이력 |
| 출력 | 대사 일치 건, 금액 차이 건, 상태 불일치 건, 재처리 후보, 수동 보정 큐, 외감 증적 이벤트 |
| 인수조건 | 거래 ID 기준 중복 대사를 방지한다. 금액 차이와 기간 경계 이슈는 자동 완료하지 않는다. 재처리는 멱등 키를 사용하고 실패 시 재시도 횟수와 사유를 기록한다. |
| 의존성 | Settlement & Point Ops, Integration Hub, Profitability Dashboard, Security & Audit, 공급사/결제 원천 데이터 |
| 담당 | A5 주관, A4 수익성 지표, A6 연동, A7 외감/감사, A8 운영 검증 |
| KPI 영향 | 정산 대사 자동화율, 평균 대사시간, 예외율, 재처리 성공률, 외감 증적 준비시간 |

결정: 정산은 자동 지급 확정이 아니라 자동 대사·차이 검출·재처리 후보 생성부터 시작한다.

인당 생산성/마진 기여: 정산 담당자의 반복 대사 시간을 줄이고 오류를 조기 탐지해 보정 비용과 공급사 문의를 낮춘다.

### 6.4 총무대행 의료비 접수

| 항목 | 내용 |
|---|---|
| 목적 | 의료비 신청의 필수 입력, 첨부 누락, 고객사 정책 한도, 중복 가능성을 자동 점검하고 사람 검토 큐로 정리해 전달한다. |
| 입력 | 고객사 ID, 신청자 식별자, 신청 금액, 신청 기간, 의료비 항목 코드, 첨부 파일 메타데이터, 고객사별 복지 정책 |
| 출력 | 접수 완료 후보, 보완 요청 후보, 사람 검토 큐, 반려 후보, 검토 체크리스트 |
| 인수조건 | 민감정보 가능 첨부는 PM 승인 전 자동 OCR/내용 분석 범위로 확정하지 않는다. 필수 항목 누락은 보완 요청 후보로 표시한다. 한도 초과와 중복 의심은 사람 검토 큐로 이동한다. |
| 의존성 | Operations Console, CRM Core 고객사 정책, A7 개인정보 처리범위 승인, 첨부파일 보관/접근 통제 |
| 담당 | A5 주관, A7 개인정보/민감정보 승인 기준, A8 운영 정책 검증, PM 승인 |
| KPI 영향 | 검토 전 준비시간, 보완 요청률, 평균 처리시간, 예외율 |

결정: 의료비는 민감정보 처리범위 승인 전 자동 승인하지 않고 접수 검증과 검토 체크리스트 자동화를 우선한다.

인당 생산성/마진 기여: 고위험 개인정보 노출을 늘리지 않으면서 담당자의 서류 정리와 누락 확인 시간을 줄인다.

### 6.5 학자금 신청 접수

| 항목 | 내용 |
|---|---|
| 목적 | 학자금 신청의 기간, 금액, 대상자, 고객사 정책, 증빙 누락을 자동 점검하고 피크 시즌 검토 큐를 표준화한다. |
| 입력 | 고객사 ID, 신청자 식별자, 대상 학생 식별자, 신청 금액, 학기/기간, 학교/과정 구분, 첨부 파일 메타데이터, 고객사별 복지 정책 |
| 출력 | 접수 완료 후보, 보완 요청 후보, 사람 검토 큐, 반려 후보, 검토 체크리스트 |
| 인수조건 | 가족관계와 재학증빙 등 개인정보 처리범위는 PM 승인 전 확정하지 않는다. 기간 불일치와 한도 초과는 자동 완료하지 않는다. 반복 누락 사유는 표준 보완 요청 템플릿으로 생성된다. |
| 의존성 | Operations Console, CRM Core 고객사 정책, A7 개인정보 처리범위 승인, 첨부파일 보관/접근 통제 |
| 담당 | A5 주관, A7 개인정보 승인 기준, A8 운영 정책 검증, PM 승인 |
| KPI 영향 | 피크 시즌 평균 처리시간, 보완 요청률, 담당자 1인당 처리건수, 예외율 |

결정: 학자금은 시즌성 처리량 완화를 위해 접수 검증과 보완 요청 자동화를 우선한다.

인당 생산성/마진 기여: 특정 시즌에 필요한 임시 인력과 야근성 검토 시간을 줄인다.

## 7. 처리 상태 및 판단 기준 요약

상세 큐 스펙은 `/specs/automation/review-queue.md`에서 정의한다.

| 판단 | 기준 | 결과 |
|---|---|---|
| 자동 처리 | 필수 입력 충족, 정책/한도/권한 일치, 중복 없음, 민감정보 승인 범위 내, 금액 리스크 기준 이하 | Operations Console에서 `completed` 또는 다음 업무 단계로 이동 |
| 사람 검토 | 금액·정책·첨부·권한·개인정보 리스크가 기준을 넘거나 자동화 신뢰도가 낮음 | `needs_review` 큐로 이동 |
| 반려 | 정책상 명백히 불가하고 보완으로 해결되지 않음 | `rejected` 처리 및 표준 사유 기록 |
| 보류 | 원천 데이터 지연, 외부 연동 장애, PM 승인 대기, 고객사 정책 미확정 | `on_hold` 처리 및 해제 조건 기록 |
| 재처리 | 일시적 연동 실패, 멱등 키로 재시도 가능한 오류 | `retry_pending` 처리 후 제한 횟수 내 재시도 |

결정: 자동화 판단은 항상 자동 처리보다 사람 검토와 보류로 우회 가능한 보수적 상태 전이를 가진다.

인당 생산성/마진 기여: 자동화 오류로 생기는 고객사 신뢰 손실과 재처리 비용을 줄이면서 반복 확인 업무를 단계적으로 줄인다.

## 8. KPI 측정 기준

| KPI | 정의 | 계산식 | 측정 단위 | 비고 |
|---|---|---|---|---|
| 자동화율 | 접수 건 중 사람 개입 없이 자동 완료 또는 다음 단계로 이동한 비율 | 자동 처리 완료 건수 / 전체 접수 건수 | 업무유형·고객사·일 단위 | 의료비/학자금은 PM 승인 전 자동 완료가 아니라 자동 검증률로 별도 표기 |
| 자동 검증률 | 자동화가 필수 입력, 중복, 한도, 권한 등 검증 결과를 생성한 비율 | 자동 검증 완료 건수 / 전체 접수 건수 | 업무유형·고객사·일 단위 | 고위험 업무의 1차 KPI |
| 평균 처리시간 | 접수부터 완료/반려/보완요청까지 걸린 평균 시간 | 완료 시각 - 접수 시각의 평균 | 분 또는 시간 | 보류 시간 포함/제외를 별도 집계 |
| 사람 검토 평균시간 | 사람이 큐에서 열람한 뒤 결정하기까지 걸린 시간 | 결정 시각 - 첫 열람 시각의 평균 | 분 | 검토 UI 개선 효과 측정 |
| 예외율 | 자동 처리되지 않고 사람 검토·보류·재처리로 이동한 비율 | 예외 건수 / 전체 접수 건수 | 업무유형·고객사·사유별 | 자동화 룰 개선 후보 식별 |
| 재처리 성공률 | 재처리 대상 중 자동 재처리로 해결된 비율 | 재처리 성공 건수 / 재처리 대상 건수 | 연동·업무유형별 | Integration Hub 안정성 지표 |
| 담당자 1인당 처리건수 | 운영 담당자별 완료/반려/보완요청 처리량 | 처리 완료 건수 / 활성 담당자 수 | 일·주·월 단위 | 업무량과 인력 생산성 기준 |

결정: 자동화율은 "사람 미개입 완료"로 엄격히 정의하고, 의료비·학자금처럼 민감정보 검토가 필요한 업무는 자동 검증률을 별도 KPI로 둔다.

인당 생산성/마진 기여: 자동화 효과를 과장하지 않고 실제 인력 투입 감소와 처리시간 단축을 분리해 측정한다.

## 9. 공통 인수조건

- 자동화 대상 업무는 모두 Operations Console의 표준 업무 ID를 가진다.
- 자동화 판단 결과는 자동 처리, 사람 검토, 반려, 보류, 재처리 중 하나로 기록된다.
- 자동화 판단 사유, 적용 규칙 버전, 입력 데이터 참조, 담당자 수동 변경 이력은 감사로그로 남긴다.
- 민감정보 또는 고위험 개인정보가 포함될 수 있는 입력 항목은 PM 김권일 승인 전 확정하지 않는다.
- 고객사별 정책, 한도, SLA가 없거나 충돌하면 자동 처리하지 않고 사람 검토 또는 보류로 이동한다.
- 자동화 KPI는 고객사, 업무유형, 담당팀, 기간 단위로 집계 가능해야 한다.
- 반려와 보완 요청은 표준 사유 코드와 사용자 표시 문구를 분리해 관리한다.

결정: MVP 자동화는 "운영 콘솔에서 추적 가능한 결정"만 허용하고, 별도 RPA 화면에서만 처리되는 블랙박스 자동화는 제외한다.

인당 생산성/마진 기여: 자동화 결과를 같은 운영 흐름에서 추적해 누락, 중복 대응, 감사 확인에 드는 시간을 줄인다.

## 11. PM 승인 필요 항목

1. 의료비와 학자금 첨부파일에서 자동 분석 가능한 개인정보/민감정보 항목, 보관기간, 접근권한 범위
2. OCR, AI 분류, 외부 RPA 솔루션, 외부 위탁 처리 도입 여부와 예산
3. 자동 승인 가능한 금액 한도, 고객사별 예외 정책, 사후 샘플링 감사 비율
4. 자동 반려를 허용할 업무유형과 사용자 고지 문구의 법무 검토 필요 여부
5. 자동화 로그와 원천 증빙의 보관기간 및 외감 제출 범위

인당 생산성/마진 기여: 승인 게이트를 명시해 고위험 자동화의 중단·수정 비용을 줄이고 수익성 높은 범위부터 실행하게 한다.
