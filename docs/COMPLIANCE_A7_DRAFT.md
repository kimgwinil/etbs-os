# A7 컴플라이언스/보안 초안

## 1. 문서 목적

이 문서는 이제너두 전사 CRM OS MVP의 `Security & Audit Baseline`을 컴플라이언스 관점에서 구체화한 A7 초안이다. RBAC, 테넌트 격리, 개인정보 접근로그, 감사로그, 보존정책, 개인정보 흐름도, 위험-통제 매핑, 외감 대응 증적 요구사항을 정의한다.

본 문서는 개발 확정안이 아니며, 예산, 외부계약, 개인정보 처리범위, 민감정보 항목, 보관기간, 위탁/재위탁 범위, 아키텍처 확정은 PM 김권일 승인 전 확정하지 않는다.

인당 생산성/마진 기여: 보안과 컴플라이언스를 MVP 기본 요구로 내재화해 사후 보완, 감사 대응, 권한 재정비, 정산 증적 수집에 드는 반복 인력을 줄인다.

## 4. 범위

### 4.1 포함

- RBAC 역할, 권한, 승인 흐름 초안
- 고객사, 공급사, 임직원, 플랫폼 운영자 기준 테넌트 격리 원칙
- 개인정보 접근로그 기록 대상, 필수 필드, 검증 기준
- 감사로그 기록 대상, 외감 증적 연계 기준
- 보존정책 초안과 PM 승인 필요 항목
- 개인정보 흐름도 초안
- ISMS, 개인정보, 외감 대응 요구 분리 정리
- 임직원정보, 권한별 메뉴, 슈퍼바이저 대시보드, 결재라인 통제
- 견적, 계약, 주문, 출고, 세금계산서/거래명세표, 매출인식, 영업이익 산식 변경 증적
- 고객정보, 임직원정보, 매출정보, 상품정보의 생성/수정/삭제/조회 타임로그와 감사로그 요구
- 설정 메뉴 하위 `로그기록` 확인 메뉴 접근 통제와 필터 요구
- 영업활동부터 매출인식까지의 타임로그/감사로그 요구
- 임직원-거래처 다대다 담당 배정 변경 권한, 거래처별 담당자 노출 범위, 배정 변경 타임로그 요구
- 결재/승인/반려/보류 버튼 의미, 권한 없는 결재 버튼 차단, 승인/반려/보류 사유 로그와 보류 상태 감사 증적 요구
- 입사등록 결재 승인 전 임직원 계정 활성화와 권한 부여 차단 요구
- 입사등록 개인정보/임직원정보 처리범위 승인 게이트 요구
- 메뉴별 로그의 개인정보 마스킹, 메뉴 진입/조회/수정/결재/반출 로그 보존과 접근권한 요구
- 제원원가, 판관비, 일반관리비 입력 권한 제한, 권한 부여/회수 로그, 비용 변경 전후 값 감사로그 요구
- 외주 인력 외부 접속 보안 검토안, 공개 IP 직접 개방 비권고, VPN/허용 IP/Zero Trust/임시 터널 후보 비교
- 팀 채팅방의 개인대개인, 단톡방, 참여자 선택 방식에 대한 개인정보 노출 범위, 초대 권한, 메시지/파일 감사로그 요구
- A1/A2/A4/A6/A8/A9 반영 체크리스트

인당 생산성/마진 기여: 고위험 통제를 MVP 공통 요구로 고정해 각 모듈이 따로 보안 설계를 반복하지 않게 한다.

### 4.2 제외

- 개인정보 및 민감정보 항목 확정: PM 승인 필요
- 개인정보 처리 목적, 처리범위, 보관기간 확정: PM 승인 필요
- 특정 DB, 로그 저장소, SIEM, IAM, DLP, 클라우드 제품 선정: PM 승인 필요
- 외부 위탁/재위탁, 제3자 제공, 해외 이전 여부 확정: PM 승인 필요
- 정산 회계 기준, 세금/수수료/반올림 공식 확정: PM 승인 필요
- 외부 감사 제출 양식 및 보존기간 최종 확정: PM 승인 필요

인당 생산성/마진 기여: 승인 없는 고비용 결정을 차단해 불필요한 개발비와 계약 리스크를 줄인다.

## 6. 주요 가정

- 가정: 레거시 시스템, 베네카페, 결제, 온누리, 공급사 API의 상세 스키마와 계약 문서는 아직 제공되지 않았다.
- 가정: 임직원 약 260만 명 이상 규모를 고려해 개인정보 접근로그와 감사로그는 대량 생성될 수 있다.
- 가정: MVP는 실데이터 원본이 아닌 비식별/샘플 데이터로 우선 검증한다.
- 가정: 민감정보가 포함될 수 있는 복지 항목, 의료비, 가족정보, 증빙자료는 PM 승인 전 처리범위를 확정하지 않는다.
- 가정: 외감 대응은 정산, 포인트, 승인, 변경 이력의 추적 가능성을 MVP 기본 요건으로 본다.
- 가정: `/docs/PROCESS_REQUIREMENTS.md`의 MVP 영업이익 산식은 `salesAmount - (salesAmount * 0.5) - (salesAmount * 0.5)`를 기준 후보로 반영하되, 공식 회계 산식 확정은 PM 승인 대상이다.
- 가정: 세금계산서/거래명세표 외부 발행 연동 방식, 택배사 실시간 위치 연동, 전자문서 보존 방식은 아직 확정되지 않았다.
- 가정: 담당 역할은 주담당, 부담당, 승인담당, 참조담당 후보로 시작하되 최종 역할명과 배정 변경 권한은 PM 승인 전 확정하지 않는다.
- 가정: `결재` 버튼은 상태 변경이 아니라 결재 상세 또는 처리 화면 진입 후보로 보며, `보류`를 공식 결재 상태로 둘지는 PM 승인 대상이다.
- 가정: 입사등록 대상자 정보, 소속/부서, 직무/권한 후보의 개인정보/임직원정보 처리범위는 PM 승인 전 확정하지 않는다.
- 가정: 최종 승인 후 계정 활성화는 자동 또는 관리자 확인 후 처리 중 하나로 결정해야 하며, 방식 확정 전에는 `employee_activation_pending` 상태를 통제 기준으로 둔다.
- 가정: 메뉴별 로그 보존기간과 반출 가능 권한은 감사로그 보존정책 후보에 포함하되 PM 승인 전 확정하지 않는다.
- 가정: `제원원가`는 PM 표현을 유지하며 제조원가, 상품원가, 기타 원가 중 정확한 회계 의미는 PM 승인 전 확정하지 않는다.
- 가정: 수익성 비용 입력 변경을 항상 결재 대상으로 둘지, 영향 범위가 큰 변경만 결재 대상으로 둘지는 PM 승인 대상이다.
- 가정: 외주 인력 외부 접속 대상은 원칙적으로 `dev` 또는 `staging` 환경이며, 운영 환경 접속과 공개 IP 직접 개방은 PM/A7/A9 명시 승인 전 금지한다.
- 가정: 외주 접속 환경에는 실데이터, 개인정보, 민감정보, 운영 시크릿을 노출하지 않고 샘플 데이터 또는 마스킹 데이터를 기본으로 사용한다.
- 가정: 팀 채팅은 개인대개인, 단톡방, 참여자 선택 방식 후보를 지원하되 외부 사용자 초대, 참여자 검색 필드, 메시지/파일 원문 보존 범위는 PM 승인 전 확정하지 않는다.
- 가정: 채팅 메시지와 파일에 개인정보 또는 민감정보가 포함될 수 있으므로 기본 정책은 원문 최소 보존, 메타데이터 감사로그, 첨부파일 다운로드 제한, 필요 시 마스킹/차단 후보로 둔다.

인당 생산성/마진 기여: 불확실성을 가정으로 표시해 잘못된 전제 기반 구현과 폐기 비용을 줄인다.

인당 생산성/마진 기여: 설정 메뉴에서 로그를 빠르게 찾게 해 운영, 재무, 보안 담당자의 원인 조사 시간을 줄인다.

## 11.3 외주 인력 외부 접속 보안 검토안

공개 IP 직접 개방은 로컬 개발 PC, 검증 서버, 운영 시스템, 소스, 개인정보, 운영 데이터 노출 위험이 커서 비권고한다. 외주 접속은 PM 승인, A7 보안 검토, A9 접속 환경 검토 후 `dev` 또는 `staging` 환경에 한정해 허용한다.

| 접속 방식 후보 | 보안 검토 | 권고 | 필수 통제 | 인당 생산성/마진 기여 |
|---|---|---|---|---|
| VPN | 계정 또는 외주 고정 IP 기반으로 검증망 접근 | 1순위 후보 | 개인별 계정, 만료일, MFA 후보, 접속로그, 최소권한 | 검수 지연을 줄이면서 접근 범위를 중앙에서 회수한다. |
| 허용 IP 목록 | 외주 고정 IP만 `dev`/`staging` 접근 허용 | 2순위 후보 | 고정 IP 확인, 기간 제한, 메뉴별 로그, 다운로드 차단 | 구현 난이도를 낮추되 무단 위치 접근을 줄인다. |
| Zero Trust Access | 계정, MFA, 정책 기반 웹 접근 | 2순위 후보 | 사용자/기기/위치 정책, 세션 로그, 만료일 | 외주별 접근 범위를 세밀하게 관리해 권한 점검 시간을 줄인다. |
| 임시 터널 | 단기 검수용 임시 URL | 긴급 검수 후보 | 짧은 만료, IP/계정 제한, 샘플 데이터, 접속 종료 후 회수 | 단기 검수 병목을 풀되 상시 노출을 방지한다. |
| 공개 IP 직접 개방 | 서버/로컬 포트를 인터넷에 직접 노출 | 비권고 | PM/A7/A9 명시 승인 없이는 금지 | 사고 대응과 보안 재작업 비용을 예방한다. |

| 통제 항목 | 요구사항 | 인수조건 |
|---|---|---|
| 계정 | 외주 계정은 개인별로 발급하고 공유 계정을 금지한다. | 외주 업체명, 담당자 이름/이메일, 접속 목적, 만료일이 기록되어야 한다. |
| 인증 | MFA 또는 이에 준하는 추가 인증을 후보로 둔다. | MFA 적용 여부는 PM 승인 전 확정하지 않고 미적용 시 대체 통제를 기록한다. |
| 권한 | 필요한 메뉴와 기능만 최소권한으로 부여한다. | 권한 없는 메뉴 진입, 조회, 변경, 다운로드 시도는 `permission_denied` 로그로 남아야 한다. |
| 데이터 | 개인정보와 운영 데이터는 마스킹 또는 샘플 데이터로 제공한다. | 실데이터, 운영 시크릿, 개인정보 원문 노출은 기본 차단되어야 한다. |
| 다운로드 | 다운로드/반출은 기본 차단한다. | 예외 허용 시 승인 ID, 대상, 건수, 만료일, 사유가 감사로그에 남아야 한다. |
| 로그 | 접속, 로그인 실패, 메뉴 진입, 조회, 변경, 결재, 반출 요청을 기록한다. | 메뉴별 로그와 외주 접속 로그를 외주 사용자 ID로 조회할 수 있어야 한다. |
| 회수 | 기간 종료 후 계정, 허용 IP, 터널, 정책을 회수한다. | 만료 계정과 미회수 정책이 조회되어야 하며 회수 이력이 남아야 한다. |

인당 생산성/마진 기여: 외주가 필요한 화면을 검수할 수 있게 하면서 과도한 노출과 계정 방치로 인한 사고 비용을 줄인다.

## 11.4 팀 채팅 개인정보/감사로그/권한 기준

| 채팅 방식 | 허용 범위 | 주요 통제 | 인수조건 |
|---|---|---|---|
| 개인대개인 | 업무상 필요한 내부 임직원 간 1:1 대화 | 참여자 검색 최소 표시, 외부 초대 차단, 메시지/파일 로그 | 참여자 외 사용자는 대화방과 첨부파일을 조회할 수 없어야 한다. |
| 단톡방 | 부서, 프로젝트, 업무 단위 내부 참여자 대화 | 방 생성 권한, 참여자 추가 권한, 참여자 목록 접근 제한 | 권한 없는 참여자 추가와 외부 사용자 초대가 `permission_denied`로 남아야 한다. |
| 참여자 선택 | 부서/이름/권한 후보로 내부 참여자 선택 | 부서/이름/권한 표시 최소화, 검색 결과 마스킹, 테넌트/부서 범위 제한 | 참여자 선택 결과는 승인된 조직 범위와 표시 필드로 제한되어야 한다. |

| 통제 항목 | 요구사항 | 인수조건 |
|---|---|---|
| 참여자 표시 | 부서, 이름, 권한 표시 범위는 최소 필요 정보로 제한한다. | 권한명은 업무상 필요한 범주로 축약하고 상세 권한/개인정보 원문은 PM 승인 전 노출하지 않는다. |
| 방 생성 | 채팅방 생성자는 방 유형, 목적, 참여자, 테넌트 범위를 기록한다. | `chat_room_id`, 생성자, 참여자 수, 방 유형, 목적이 감사로그에 남아야 한다. |
| 참여자 추가 | 참여자 추가/제거는 행위자, 대상자, 사유, 결과를 기록한다. | 외부 사용자, 타 테넌트, 권한 없는 사용자는 초대가 차단되어야 한다. |
| 메시지 전송 | 메시지 전송은 원문 최소 보존 후보로 두고 메타데이터와 콘텐츠 분류 결과를 기록한다. | 개인정보/민감정보 탐지 후보, 메시지 해시, 전송자, 수신 범위, 시각, 결과가 남아야 한다. |
| 파일 첨부 | 파일 첨부는 파일명, 유형, 크기, 마스킹 여부, 다운로드 권한, 보존기간 후보를 기록한다. | 개인정보/민감정보 가능 파일은 다운로드 제한, 마스킹, 승인 게이트 후보를 가져야 한다. |
| 로그 조회 | 채팅 로그 조회는 보안/감사 목적과 권한을 요구한다. | 채팅 로그 상세 조회와 반출 요청 자체도 감사로그로 남아야 한다. |

인당 생산성/마진 기여: 협업 채팅의 처리 속도는 유지하면서 초대 오류, 파일 반출, 개인정보 메시지 조사 비용을 줄인다.

## 12. 테넌트 격리 초안

| 데이터 영역 | 기본 격리 키 | 접근 원칙 | 예외 조건 |
|---|---|---|---|
| 고객사 | `customer_company_id` 또는 `customer_account_id` | 고객사별 데이터 분리 | 전사 운영 승인 접근 |
| 공급사 | `supplier_id` 또는 `supplier_account_id` | 공급사별 데이터 분리 | 정산/계약 담당 승인 접근 |
| 임직원 | `employee_id`, `customer_company_id` | 고객사 소속 기준 분리 | 업무 배정, 승인, 접근로그 필요 |
| 계약 | `contract_id`, 관련 고객사/공급사 ID | 계약 당사자와 담당자 범위 | 법무/재무 승인 접근 |
| 포인트/정산 | `settlement_id`, `point_account_id`, 관련 테넌트 ID | 정산 담당 범위 | 외감 증적 조회, 승인 필요 |
| CS/운영 업무 | `case_id`, `work_item_id`, `tenant_scope` | 배정자와 담당 조직 범위 | SLA 장애 대응, 사후 검토 필요 |
| 로그/증적 | `tenant_scope`, `domain`, `object_id` | 보안/감사 역할 제한 | 외감 제출 승인 필요 |
| 영업 프로세스 | `sales_activity_id`, `pipeline_id`, `quote_id`, `order_id` | 담당자/팀/슈퍼바이저 범위 | 결재 및 산식 변경 승인 필요 |
| 세금계산서/거래명세표 | `invoice_id`, `statement_id`, `order_id`, `customer_account_id` | 발행 담당, 관리자, 재무/감사 범위 | 취소/재발행 승인 필요 |
| 매출인식/영업이익 | `revenue_id`, `profit_formula_version`, `customer_account_id` | 집계 우선, 산식 변경 제한 | 회계 기준 PM 승인 필요 |
| 임직원-거래처 담당 배정 | `assignment_id`, `employee_account_id`, `customer_account_id` | 담당 역할, 대표 담당자, 유효기간 기준 | 배정 변경 권한 PM 승인 필요 |
| 입사등록/계정 활성화 | `onboarding_id`, `approval_id`, `employee_id` | 승인 전 후보 정보와 활성 계정 분리 | 개인정보 처리범위 PM 승인 필요 |
| 메뉴별 로그 | `menu_id`, `route_id`, `event_id` | 로그 조회 권한과 업무 처리 권한 분리 | 보존/반출 권한 PM 승인 필요 |
| 수익성 비용 입력 | `cost_input_id`, `profit_formula_version`, `actor_user_id` | `Master` 또는 입력 권한 임직원만 입력 | 회계 의미/결재 대상 PM 승인 필요 |
| 외주 접속 | `vendor_user_id`, `vendor_company_id`, `access_policy_id` | `dev`/`staging`, 만료일, 개인별 계정 기준 | 접속 방식/데이터 범위 PM 승인 필요 |
| 팀 채팅 | `chat_room_id`, `message_id`, `attachment_id`, `participant_user_id` | 내부 참여자, 테넌트/부서/업무 범위 기준 | 참여자 표시/메시지 보존 PM 승인 필요 |

인당 생산성/마진 기여: 데이터 영역별 격리 키를 고정해 화면/API/다운로드별 중복 권한 설계를 줄인다.

## 16. 개인정보 흐름도 초안

```text
고객사/공급사/임직원/레거시 입력
  -> CRM Core
     -> Operations Console
        -> 업무/CS 처리 이력
        -> 개인정보 접근로그
     -> Settlement & Point Ops
        -> 포인트 원장
        -> 정산/회계 증적
        -> 감사로그
     -> Integration Hub
        -> 베네카페/결제/온누리/공급사 API
        -> 개인정보 접근로그
        -> 감사로그
     -> Sales Process
        -> 영업활동/파이프라인/견적/계약/주문/출고/배송
        -> 세금계산서/거래명세표
        -> 매출인식/영업이익 산식
        -> 결재라인/타임로그/감사로그
     -> Profitability Dashboard
        -> 집계/비식별 지표/슈퍼바이저 대시보드

개인정보 접근로그 -> 보안/개인정보 검토
감사로그 -> 외감/내부통제 증적
```

|---|---|---|---|
| 원천 입력 -> CRM Core | 높음 | 최소 수집, 테넌트 키, 암호화 후보, 접근 제한 | 항목 PM 승인 필요 |

| CRM Core -> Integration Hub -> 외부 시스템 | 중간~높음 | 전송 최소화, 전송로그, 위탁 검토, 마스킹 | 전송 항목 PM 승인 필요 |
| CRM/Ops/Settlement -> Dashboard | 낮음 목표 | 집계/비식별화, 상세 드릴다운 제한 | 초안 |

## 22. KPI 영향

| KPI | 측정 방향 |
