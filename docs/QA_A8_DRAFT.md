# A8 QA 초안: MVP 인수조건 검증 전략

## 1. 문서 목적

이 문서는 이제너두 전사 CRM OS MVP의 P0/P1 모듈을 운영 품질 관점에서 검증하기 위한 QA 기준선이다. 기능 존재 여부보다 운영자 처리량 증가, 오류 감소, 회귀 자동화 가능성, 감사 대응 가능성을 우선 검증한다.

인당 생산성/마진 기여: QA 기준을 처리량과 오류 비용 중심으로 고정해 개발 완료 후에도 운영 인력이 늘어나는 결과를 방지한다.

## 2. 검증 원칙

1. 모든 P0/P1 스토리는 목적, 입력, 출력, 인수조건, 의존성, 담당, KPI 영향을 가진 경우에만 인수 후보가 된다.
2. 심사, 정산, 포인트, CS는 MVP 단계부터 회귀 자동화 대상 플로우로 분류한다.
3. 개인정보 처리범위, 외부계약, 예산, 아키텍처 확정은 PM 김권일 승인 전 QA 통과 조건으로 확정하지 않는다.
4. E2E 테스트는 운영자의 실제 처리 경로를 검증하고, API/데이터 테스트는 대량 처리와 정합성 리스크를 검증한다.
5. 보안/권한 테스트는 기능 테스트의 후행 검사가 아니라 모든 핵심 플로우의 기본 통과 조건이다.

인당 생산성/마진 기여: 초기부터 반려 기준을 명확히 해 불완전한 기능이 운영 현장으로 넘어가며 발생하는 재처리 비용을 줄인다.

## 3. 가정

- 가정: 레거시 시스템, 베네카페, 결제, 온누리 연동의 상세 API 문서는 아직 제공되지 않았다.
- 가정: MVP QA는 실제 운영 데이터 원본이 아닌 비식별 샘플 데이터와 계약/정산/포인트 시뮬레이션 데이터로 먼저 수행한다.
- 가정: 개인정보 및 민감정보 항목, 보관기간, 위탁/재위탁 범위는 PM 김권일 승인 후 확정한다.
- 가정: "자동심사"는 MVP에서 무검토 자동 승인보다 후보 추천, 예외 분류, 사람 검토 큐 연결을 우선 검증한다.

인당 생산성/마진 기여: 불확실성을 가정으로 분리해 잘못된 데이터와 연동 전제에 따른 재작업을 줄인다.

## 5. 핵심 플로우별 테스트 시나리오

### 5.1 심사 플로우

목적: 신청 접수부터 자동심사 후보 분류, 사람 검토, 승인/보류/반려, 이력 저장까지 운영 누락 없이 처리되는지 검증한다.

입력: 신청 ID, 고객사 ID, 임직원 ID, 증빙 상태, 심사 규칙 결과, 담당자 역할.

출력: 심사 상태, 담당자 배정, 승인/보류/반려 사유, 감사로그, CS 전환 가능 이력.

인수조건:

- 접수된 신청은 운영 큐에 1건만 생성된다.
- 자동심사 후보, 보류, 반려 추천은 근거 코드와 함께 저장된다.
- 담당자가 상태를 변경하면 변경 전후 값, 사용자, 시각, 사유가 감사로그에 남는다.
- 권한 없는 사용자는 타 고객사 신청을 조회하거나 처리할 수 없다.
- 반려된 신청은 재접수 또는 CS 문의 전환 경로가 명확하다.

반려 기준:

- 동일 신청이 중복 큐로 생성된다.
- 반려 사유 없이 상태가 반려로 변경된다.
- 자동심사 결과의 근거가 저장되지 않는다.
- 개인정보 접근 로그 없이 증빙 또는 임직원 정보가 조회된다.

의존성: CRM Core, Operations Console, Security & Audit Baseline, Automation/RPA Workbench.

담당: A8 검증, A2 운영 큐, A5 자동심사, A7 개인정보 기준, A9 보안 구현.

KPI 영향: 평균 심사 처리시간, 심사자 1인당 처리 건수, 반려 후 재문의율, 자동분류율.

인당 생산성/마진 기여: 심사 기준과 예외를 회귀 테스트로 고정해 신규 신청 증가에도 심사 인력 증가를 억제한다.

### 5.2 정산 플로우

목적: 거래/포인트/공급사/고객사 기준으로 정산 금액과 증적이 일치하고 예외가 운영 큐로 분리되는지 검증한다.

입력: 거래 ID, 공급사 ID, 고객사 ID, 정산 기간, 수수료율, 취소/환불, 포인트 사용/복원 이벤트.

출력: 정산 배치, 공급사별 정산 금액, 예외 목록, 회계 증적, 변경 감사로그.

인수조건:

- 같은 정산 배치를 재실행해도 중복 지급 또는 중복 차감이 발생하지 않는다.
- 거래 합계, 취소/환불, 포인트 사용/복원 금액이 정산 결과와 대사된다.
- 정산 예외는 원인 코드, 담당자, SLA, 재처리 버튼 또는 수동 보정 경로를 가진다.
- 정산 결과의 원천 데이터와 계산 버전을 추적할 수 있다.
- 회계 증적 다운로드 또는 조회 시 권한과 접근로그가 적용된다.

반려 기준:

- 정산 재실행 시 결과가 달라지는데 원인 추적이 불가능하다.
- 취소/환불 거래가 정산 금액에서 누락된다.
- 예외 건이 큐에 남지 않고 단순 실패로 종료된다.
- 금액 반올림, 세금, 수수료 기준이 명시되지 않았다.

의존성: Settlement & Point Ops, CRM Core, Profitability Dashboard, Integration Hub.

담당: A8 검증, A4 지표/대사, A6 연동, A7 회계/감사 기준.

KPI 영향: 정산 오류율, 정산 문의 건수, 월마감 소요시간, 외감 증적 준비시간.

인당 생산성/마진 기여: 정산 오류와 월마감 수작업을 줄여 재무/운영 인력의 반복 검산 비용을 낮춘다.

### 5.3 포인트 플로우

목적: 포인트 지급, 차감, 사용, 취소, 복원, 만료가 잔액과 정산 근거에 정확히 반영되는지 검증한다.

입력: 임직원 ID, 고객사 ID, 포인트 정책, 지급 이벤트, 사용 거래, 취소/복원 이벤트, 만료일.

출력: 포인트 원장, 현재 잔액, 거래별 포인트 이력, 정산 참조값, 예외 큐.

인수조건:

- 모든 포인트 변화는 원장 이벤트로 기록되고 현재 잔액은 원장 합계와 일치한다.
- 지급/차감/취소/복원/만료 이벤트는 멱등 키를 가진다.
- 음수 잔액, 중복 지급, 만료 후 사용은 차단되거나 예외 큐로 분리된다.
- 고객사별 포인트 정책 차이가 테스트 데이터로 검증된다.
- 포인트 원장 조회는 역할과 테넌트 격리를 통과해야 한다.

반려 기준:

- 잔액만 변경되고 원장 이벤트가 남지 않는다.
- 동일 이벤트 재처리로 포인트가 중복 변동된다.
- 고객사 정책이 다른데 같은 규칙으로 처리된다.
- 포인트 변경이 정산 참조값과 연결되지 않는다.

의존성: Settlement & Point Ops, Security & Audit Baseline, CRM Core.

담당: A8 검증, A4 원장/지표, A6 외부 이벤트, A9 권한 통제.

KPI 영향: 포인트 오류율, 잔액 문의 건수, 수동 보정 건수, 정산 대사 시간.

인당 생산성/마진 기여: 포인트 원장 회귀를 자동화해 잔액 문의와 수동 보정에 들어가는 운영 시간을 줄인다.

### 5.4 CS 플로우

목적: 고객사, 임직원, 공급사 문의가 기준 데이터와 업무 큐에 연결되어 중복 응대와 누락을 줄이는지 검증한다.

입력: 문의 ID, 문의자 유형, 고객사/공급사/임직원 참조 ID, 카테고리, SLA, 관련 거래/신청/정산 ID.

출력: CS 티켓, 담당자 배정, 관련 업무 링크, 답변/보류/이관/완료 상태, 활동 이력.

인수조건:

- 문의는 관련 고객사/공급사/임직원/거래/신청 중 최소 하나의 기준 데이터와 연결된다.
- 동일 문의의 중복 접수 후보가 표시된다.
- SLA 초과 위험 건은 필터와 우선순위로 확인 가능하다.
- CS 처리 이력은 CRM 활동 이력과 감사로그에 남는다.
- 개인정보 포함 문의는 마스킹, 접근권한, 접근로그 기준을 따른다.

반려 기준:

- 티켓이 기준 데이터 없이 독립 메모로만 저장된다.
- 담당자 변경 또는 이관 이력이 남지 않는다.
- SLA 상태가 계산되지 않거나 필터링되지 않는다.
- 개인정보가 권한 없는 역할에 노출된다.

의존성: CRM Core, Operations Console, Security & Audit Baseline.

담당: A8 검증, A2 운영 콘솔, A3 CS 화면, A7 개인정보 기준.

KPI 영향: 평균 응답시간, SLA 준수율, 중복 문의율, 담당자 1인당 처리 건수.

인당 생산성/마진 기여: CS를 기준 데이터와 연결해 반복 확인 시간을 줄이고 동일 인력의 처리량을 높인다.

## 6. 회귀 자동화 기준

| 플로우 | 자동화 레벨 | 최소 자동화 케이스 | 자동화 진입 기준 | 릴리즈 차단 기준 |
|---|---|---|---|---|
| 심사 | E2E + API + 권한 | 접수, 자동분류, 담당자 배정, 보류, 승인, 반려, 재접수 | 상태 전이 API와 운영 큐 UI가 존재 | 중복 큐, 권한 우회, 근거 없는 반려 |
| 정산 | API + 데이터 + 연동 실패 | 배치 생성, 재실행 멱등성, 취소/환불 반영, 예외 큐, 증적 조회 | 정산 원천 데이터와 배치 ID가 정의 | 금액 불일치, 중복 정산, 예외 미기록 |
| 포인트 | API + 데이터 + 권한 | 지급, 차감, 사용, 취소, 복원, 만료, 잔액 대사 | 원장 이벤트와 멱등 키가 정의 | 원장/잔액 불일치, 중복 변동, 음수 잔액 |
| CS | E2E + API + 권한 | 접수, 중복 후보, 배정, SLA, 이관, 완료, 활동 이력 | 티켓과 CRM 엔티티 연결이 정의 | 기준 데이터 미연결, SLA 누락, 개인정보 노출 |

인당 생산성/마진 기여: 고반복 업무를 자동 회귀로 묶어 릴리즈마다 수동 QA와 운영 재확인 비용을 줄인다.

## 8. MVP 공통 반려 기준

다음 항목 중 하나라도 해당하면 MVP QA는 해당 스토리를 반려한다.

- 목적, 입력, 출력, 인수조건, 의존성, 담당, KPI 영향 중 하나가 누락된 스토리.
- 운영 상태 변경이 감사로그 없이 수행되는 기능.
- 권한 없는 사용자가 타 고객사 또는 민감 데이터에 접근 가능한 기능.
- 포인트/정산/연동 처리에서 멱등성 기준이 없는 기능.
- 실패 또는 예외가 운영 큐로 남지 않아 사람이 추적할 수 없는 기능.
- 대시보드 지표의 원천 데이터와 계산 기준이 추적되지 않는 기능.
- 자동화 후보 기능이 오탐/오처리 시 수동 보정 경로를 제공하지 않는 기능.

인당 생산성/마진 기여: 반려 기준을 명시해 운영 비용을 키우는 불완전한 기능의 릴리즈를 차단한다.
