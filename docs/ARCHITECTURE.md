# 이제너두 전사 CRM OS 통합 아키텍처 초안

## 1. 목적

본 문서는 A1~A9 담당자 초안과 `/docs/PRD.md`, `/docs/PROCESS_REQUIREMENTS.md`를 취합한 팀장 통합 아키텍처 초안이다. 본 문서는 확정안이 아니며, 아키텍처 확정, 외부계약, 개인정보 처리범위, 예산은 PM 김권일 승인 후 진행한다.

인당 생산성/마진 기여: 영업부터 매출인식까지 하나의 운영 흐름으로 통합해 재입력, 누락, 수기 검산, 부서 간 확인 비용을 줄인다.

## 2. MVP 아키텍처 방향

MVP는 "유통회사 표준 Lead-to-Cash 운영 OS"를 기준으로 구성한다.

```text
영업활동
  -> 영업파이프라인
  -> 견적
  -> 계약
  -> 주문
  -> 출고
  -> 배송/입출고
  -> 세금계산서/거래명세표
  -> 매출인식
  -> 영업이익 대시보드
```

핵심 모듈은 다음으로 분리한다.

| 모듈 | 책임 | 주 담당 |
|---|---|---|
| `CRM Core` | 고객, 임직원, 공급사, 상품, 계약, 활동 기준정보 | A1, A2, A4 |
| `Sales Pipeline` | 영업활동, 기회, 견적, 계약 전환 | A2, A3, A4 |
| `Order Fulfillment` | 주문등록, 출고, 배송/입출고 상태 | A2, A3, A6 |
| `Billing & Revenue` | 세금계산서, 거래명세표, 매출인식 | A2, A4, A7 |
| `Approval Workflow` | 결재문건, 결재라인, 승인 이력 | A2, A3, A7 |
| `Profitability Dashboard` | 실시간 매출, 고정 원가/비용, 영업이익 원인 지표 | A3, A4 |
| `Security & Audit` | 권한, 테넌트 격리, 타임로그, 감사로그 | A7, A9 |
| `Integration Hub` | 택배사, 결제, 온누리, 베네카페, 외부 API | A6, A9 |

인당 생산성/마진 기여: 모듈 책임을 업무 흐름 기준으로 분리해 각 팀이 병렬로 작업하고, 경영지표까지 끊기지 않게 한다.

## 3. 권장 기술스택 초안

| 영역 | 권고 | 근거 | PM 승인 여부 |
|---|---|---|---|
| 클라이언트 | 반응형 웹/PWA 우선 | Windows와 iOS에서 공통 운영 가능, 네이티브 앱 대비 초기 비용 낮음 | 승인 필요 |
| 프론트 구조 | SPA + 역할별 메뉴 렌더링 | 운영 콘솔, 대시보드, 결재, 목록 고정 헤더 UX에 적합 | 승인 필요 |
| 백엔드 | 모듈형 모놀리식 우선, 도메인 경계 명확화 | MVP 속도와 트랜잭션 일관성 확보, 이후 모듈 분리 가능 | 승인 필요 |
| API | REST 중심 + 이벤트 발행 | 비개발자 운영 화면과 외부 연동 어댑터 구현 난이도 낮음 | 승인 필요 |
| DB | 관계형 DB 우선 | 계약, 주문, 매출, 결재, 감사로그 등 정합성 중요 | 승인 필요 |
| 검색/집계 | 운영 DB와 분석 Projection 분리 | 대량 목록/대시보드 조회가 운영 트랜잭션을 방해하지 않게 함 | 승인 필요 |
| 비동기 처리 | Job Queue + 재시도/실패 큐 | 택배사, 결제, 온누리, 베네카페 연동 실패 대응 | 승인 필요 |
| 로그/감사 | Append-only Audit Log | 외감, ISMS, 권한 변경, 매출인식 증적 대응 | 승인 필요 |

인당 생산성/마진 기여: 초기에는 구현 속도와 운영 안정성을 우선해 과도한 분산 시스템 비용을 피하고, 외부 연동은 큐 기반으로 장애 대응 시간을 줄인다.

## 4. 주요 상태머신

### 4.1 영업파이프라인

```text
lead
  -> qualified
  -> quoted
  -> approved_quote
  -> contracted
  -> lost
```

인당 생산성/마진 기여: 영업 단계가 고정되면 담당자별 예상매출, 전환율, 지연 원인을 즉시 비교할 수 있다.

### 4.2 주문/출고/배송

```text
order_draft
  -> order_confirmed
  -> outbound_requested
  -> shipped
  -> in_transit
  -> delivered
  -> delivery_exception
  -> returned
```

인당 생산성/마진 기여: 출고와 배송 예외를 운영 큐로 자동 연결해 배송 문의와 반품 손실 대응 시간을 줄인다.

### 4.3 세금계산서/거래명세표/매출인식

```text
billing_pending
  -> statement_issued
  -> tax_invoice_issued
  -> revenue_ready
  -> revenue_recognized
  -> revenue_adjustment_requested
  -> revenue_adjusted
```

인당 생산성/마진 기여: 발행과 매출인식 단계가 분리되면 누락 청구, 지연 발행, 외감 증적 확인 시간을 줄인다.

### 4.4 결재

```text
draft
  -> submitted
  -> in_review
  -> approved
  -> rejected
  -> withdrawn
```

인당 생산성/마진 기여: 견적, 계약, 발행, 매출 조정의 승인 병목을 수치화해 결재 지연에 따른 매출 지연을 줄인다.

## 5. 외부 연동 원칙

베네카페, 결제, 온누리, 택배사, 세금계산서/거래명세표 외부 시스템은 `Integration Hub`를 통해 직접 연결한다.

공통 원칙:

- 모든 외부 요청은 `integration_request_id`와 멱등키를 가진다.
- 실패 시 즉시 업무 실패로 끝내지 않고 재시도 큐와 수동 보정 큐로 보낸다.
- 외부 응답 원문 저장 여부, 개인정보 포함 항목, 보존기간은 PM 승인 전 확정하지 않는다.
- 결제, 온누리, 베네카페, 택배사 API 계약/비용/인증 방식은 승인 필요 항목으로 둔다.

인당 생산성/마진 기여: 연동 실패를 운영자가 추적 가능한 큐로 표준화해 장애 대응과 수동 재처리 시간을 줄인다.

## 6. 권한 및 메뉴 구조

| 권한 | 기본 메뉴 | 제한 |
|---|---|---|
| 일반 | 내 영업활동, 내 파이프라인, 견적, 주문, 내 결재함 | 전사 이익/전사 로그 접근 제한 |
| 관리자 | 고객, 상품, 주문, 출고, 발행, 팀 업무 | 산식 변경, 권한 변경 제한 |
| 슈퍼바이저 | 전사 대시보드, 영업이익, 로그, 설정, 권한 관리 후보 | 개인정보 상세 접근은 별도 승인 범위만 허용 |

사용자 정보는 설정 메뉴 옆에 소속, 이름, 권한을 표시한다.

인당 생산성/마진 기여: 권한별 화면을 분리해 불필요한 탐색을 줄이고 민감정보 노출로 인한 리스크 비용을 낮춘다.

## 7. 타임로그/감사로그 원칙

다음 행위는 모두 타임로그 또는 감사로그 대상이다.

- 고객/임직원/상품/매출 정보 생성, 수정, 삭제
- 영업활동, 견적, 계약, 주문, 출고, 배송, 발행, 매출인식 상태 변경
- 결재문건 생성, 상신, 결재라인 변경, 승인, 반려
- 영업이익 산식 변경
- 슈퍼바이저 대시보드 접근 및 민감 지표 조회
- 권한 변경, 설정 변경, 외부 연동 재처리

인당 생산성/마진 기여: 문제 발생 시 원인 추적과 외감 증적 수집을 자동화해 재무/운영 인력 투입을 줄인다.

## 8. 주요 의존성

| 의존성 | 영향 | 담당 |
|---|---|---|
| 개인정보/임직원정보 처리범위 | 권한, 로그, 화면 노출, 데이터 모델 확정 | PM, A7 |
| 고정 영업이익 산식 승인 | 슈퍼바이저 대시보드, KPI, 산식 버전 관리 | PM, A4 |
| 외부 연동 계약/API | 택배, 베네카페, 결제, 온누리, 세금계산서 연동 범위 | PM, A6 |
| 회계상 매출인식 기준 | 공식 매출/영업이익과 운영 지표 구분 | PM, A4, A7 |

인당 생산성/마진 기여: 승인 의존성을 분리해 불확실한 정책 때문에 전체 MVP 설계가 멈추지 않게 한다.

## 9. 인수조건

1. A2 백엔드가 각 상태머신을 API 상태값으로 전환할 수 있어야 한다.
2. A3 프론트가 권한별 메뉴, 고정 헤더, 결재라인, 슈퍼바이저 대시보드를 화면 스펙으로 전환할 수 있어야 한다.
3. A4 데이터가 영업활동부터 매출인식까지 참조 ID를 끊김 없이 모델링할 수 있어야 한다.
4. A6 연동이 외부 시스템별 멱등, 재시도, 수동 보정 큐를 설계할 수 있어야 한다.
5. A7/A9가 타임로그, 감사로그, 접근로그, 보존정책 후보를 검증 기준으로 전환할 수 있어야 한다.

인당 생산성/마진 기여: 인수조건을 담당자별 후속 작업 가능성으로 잡아 승인 후 즉시 병렬 개발로 전환할 수 있게 한다.

## 10. PM 승인 항목

1. MVP 기술 방향을 반응형 웹/PWA + 모듈형 모놀리식 + 관계형 DB 우선으로 잡아도 되는가?
2. 영업이익 대시보드는 원가 50%, 판관비/일반관리비 50% 고정 산식을 운영 지표로 우선 적용해도 되는가?
3. 베네카페, 결제, 온누리, 택배사, 세금계산서 연동은 계약/API 확인 전까지 어댑터 스펙과 수동 보정 큐까지만 확정해도 되는가?
