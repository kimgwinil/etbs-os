# A6 통합/연동 초안

## 1. 문서 목적

이 문서는 이제너두 전사 CRM OS의 P1 범위인 Integration Hub와 Settlement & Point Ops를 대상으로 외부 연동 현황 파악 질문지, 어댑터 스펙 초안, 장애/예외 큐 운영 기준을 정의한다.

본 문서는 개발 확정안이 아니라 A6 통합/연동 담당자의 초안이며, 예산, 외부계약, 개인정보 처리범위, 아키텍처 확정은 PM 김권일 승인 후 진행한다.

인당 생산성/마진 기여: 연동별 예외 처리와 재처리 기준을 표준화해 장애 대응 시간을 줄이고 정산/포인트 오류로 인한 재작업과 손실을 낮춘다.

## 2. 기준 범위

### 포함 범위

| 영역 | 포함 항목 | 설명 |
|---|---|---|
| 베네카페 연동 | 회원/고객사/복지포인트/주문 상태 연동 | 상세 API 문서 미제공으로 가정 기반 초안 |
| 결제 연동 | 승인, 취소, 부분취소, 환불, 웹훅, 대사 | PG/간편결제/가상계좌 여부 PM 승인 필요 |
| 온누리 연동 | 상품권/포인트성 결제 또는 정산 상태 연동 | 연동 주체와 API 제공 범위 확인 필요 |
| 외부 공급사 API | 상품, 주문, 배송, 정산, 클레임 상태 | 공급사별 프로토콜 차이를 어댑터로 흡수 |
| 택배사 연동 | 송장번호, 배송상태, 실시간 현재 위치, 재조회/재시도 | 택배사 API/계약/비용 PM 승인 필요 |
| 세금계산서/거래명세표 연동 | 외부 발행, 발행 상태, 첨부/전송, 발행 로그 | 전자세금계산서/문서발행 벤더 가능성 확인 필요 |
| 정산/포인트 시스템 | 지급, 차감, 만료, 회수, 정산 근거 추적 | Settlement & Point Ops 예외 큐와 연결 |
| Integration Hub | 멱등성, 재시도, 실패 큐, 폴백, 모니터링 | 모든 외부 연동 공통 계약 |

인당 생산성/마진 기여: 연동 후보를 동일한 처리 단위로 묶어 담당자별 개별 대응과 중복 개발을 줄인다.

### 제외 범위

- 상세 API별 필드 확정
- 외부 계약 조건 또는 요금제 확정
- 개인정보 항목, 보관기간, 위탁/재위탁 범위 확정
- 정산 회계 전표 생성 방식 확정
- 택배사 API 계약, 과금 방식, 호출 한도 확정
- 세금계산서/거래명세표 외부 발행 벤더 선정 또는 계약 확정
- 특정 벤더 SDK 또는 클라우드 메시징 제품 확정

인당 생산성/마진 기여: 확정되지 않은 외부 조건을 구현 범위로 오인하지 않게 해 불필요한 개발비와 계약 리스크를 줄인다.

인당 생산성/마진 기여: 발행 상태와 실패 보정을 표준화해 세금계산서/거래명세표 누락, 재발행, 회계 확인 시간을 줄인다.

## 6. 예외 큐 및 재처리 기준

| 발행 상태 불명확 | 세금계산서/거래명세표 발행 응답 미수신 | 상태 조회 우선, 쓰기 재전송 금지 | 발행상태 `issue_confirmation_required` | 외부 발행번호 확인 후 보정 | 발행 실패율, 중복 위험 건수 |

인당 생산성/마진 기여: 자동 재시도와 수동 보정의 경계를 명확히 해 불필요한 반복 확인과 금전 오류 확산을 줄인다.

### 6.3 재처리 원칙

1. 동일 업무 이벤트는 동일 `idempotencyKey`로만 재처리한다.
2. 외부 요청 성공 여부가 불명확하면 상태 조회를 먼저 수행하고 쓰기 요청을 재전송하지 않는다.
3. 결제, 포인트, 정산 금액이 관련된 건은 자동 폐기할 수 없다.
4. 택배 배송상태 조회 실패는 조회성 재시도 후 재조회 큐로 이동하며 송장번호/택배사 수동 보정 경로를 제공한다.
5. 세금계산서/거래명세표 발행 여부가 불명확하면 외부 발행 상태 조회를 먼저 수행하고 중복 발행을 금지한다.
6. 운영자 수동 보정은 사유, 증적, 승인자, 변경 전후 상태를 기록해야 한다.
7. 개인정보가 포함된 요청/응답 원문은 마스킹 저장을 기본으로 하며 원문 보관 여부는 PM 승인 필요이다.

인당 생산성/마진 기여: 재처리 원칙을 통일해 중복 지급/중복 취소 같은 금전 손실과 감사 대응 비용을 줄인다.

### 6.4 배송/입출고 큐 분리 기준

배송/입출고 택배사 연동은 `/specs/integration/delivery-tracking.md`를 기준으로 재시도 큐, 수동 보정 큐, 배송 예외 운영 큐를 분리한다.

| 큐 | 목적 | 진입 조건 | 종료 조건 | 운영자 조치 | PM 승인 필요 |
|---|---|---|---|---|---|
| 배송 재시도 큐 | 일시적 조회 실패 자동 복구 | 타임아웃, 5xx, 네트워크 오류, 배송완료 전 장기 미갱신 | 조회 성공 또는 재시도 초과 | 모니터링, 필요 시 즉시 수동 전환 | 호출 한도, 재조회 주기, 초과 비용 |
| 배송 수동 보정 큐 | 송장/택배사/상태 오류 수동 보정 | 송장번호 누락/오류, 택배사 코드 불일치, 상태 코드 미매핑, 반복 실패 | 보정 사유/증빙/변경 전후 상태 저장 | 송장번호 입력, 택배사 선택, 배송상태 보정 | 수동 입력 권한, 감사 보존기간 |
| 배송 예외 운영 큐 | 고객/마진 영향이 큰 배송 문제 처리 | 미출고, 장기 미집하, 배송 지연, 오배송, 반송, 분실/파손 | 담당자 조치 완료와 고객/공급사 후속 처리 기록 | 고객 안내, 공급사/택배사 확인, 재배송/회수/보상 후보 등록 | SLA, 고객 안내, 보상/비용 부담 기준 |

인당 생산성/마진 기여: 큐를 역할별로 분리해 자동 복구 가능한 건과 운영자가 즉시 대응해야 할 건을 구분하고 배송 문의 처리 시간을 줄인다.
