A7 컴플라이언스/보안 초안

1. 문서 목적

이 문서는 이제너두 전사 CRM OS MVP의 Security & Audit Baseline을 컴플라이언스 관점에서 구체화한 A7 초안이다. RBAC, 테넌트 격리, 개인정보 접근로그, 감사로그, 보존정책, 개인정보 흐름도, 위험-통제 매핑, 외감 대응 증적 요구사항을 정의한다.

본 문서는 개발 확정안이 아니며, 예산, 외부계약, 개인정보 처리범위, 민감정보 항목, 보관기간, 위탁/재위탁 범위, 아키텍처 확정은 PM 김권일 승인 전 확정하지 않는다.

인당 생산성/마진 기여: 보안과 컴플라이언스를 MVP 기본 요구로 내재화해 사후 보완, 감사 대응, 권한 재정비, 정산 증적 수집에 드는 반복 인력을 줄인다.

6. 주요 가정

  • 가정: 레거시 시스템, 베네카페, 결제, 온누리, 공급사 API의 상세 스키마와 계약 문서는 아직 제공되지 않았다.
  • 가정: 임직원 약 260만 명 이상 규모를 고려해 개인정보 접근로그와 감사로그는 대량 생성될 수 있다.
  • 가정: MVP는 실데이터 원본이 아닌 비식별/샘플 데이터로 우선 검증한다.
  • 가정: 민감정보가 포함될 수 있는 복지 항목, 의료비, 가족정보, 증빙자료는 PM 승인 전 처리범위를 확정하지 않는다.
  • 가정: 외감 대응은 정산, 포인트, 승인, 변경 이력의 추적 가능성을 MVP 기본 요건으로 본다.
  • 가정: /docs/PROCESS_REQUIREMENTS.md의 MVP 영업이익 산식은 salesAmount - (salesAmount * 0.5) - (salesAmount * 0.5)를 기준 후보로 반영하되, 공식 회계 산식 확정은 PM 승인 대상이다.
  • 가정: 세금계산서/거래명세표 외부 발행 연동 방식, 택배사 실시간 위치 연동, 전자문서 보존 방식은 아직 확정되지 않았다.
  • 가정: 담당 역할은 주담당, 부담당, 승인담당, 참조담당 후보로 시작하되 최종 역할명과 배정 변경 권한은 PM 승인 전 확정하지 않는다.
  • 가정: 결재 버튼은 상태 변경이 아니라 결재 상세 또는 처리 화면 진입 후보로 보며, 보류를 공식 결재 상태로 둘지는 PM 승인 대상이다.
  • 가정: 입사등록 대상자 정보, 소속/부서, 직무/권한 후보의 개인정보/임직원정보 처리범위는 PM 승인 전 확정하지 않는다.
  • 가정: 최종 승인 후 계정 활성화는 자동 또는 관리자 확인 후 처리 중 하나로 결정해야 하며, 방식 확정 전에는 employee_activation_pending 상태를 통제 기준으로 둔다.
  • 가정: 메뉴별 로그 보존기간과 반출 가능 권한은 감사로그 보존정책 후보에 포함하되 PM 승인 전 확정하지 않는다.
  • 가정: 제원원가는 PM 표현을 유지하며 제조원가, 상품원가, 기타 원가 중 정확한 회계 의미는 PM 승인 전 확정하지 않는다.
  • 가정: 수익성 비용 입력 변경을 항상 결재 대상으로 둘지, 영향 범위가 큰 변경만 결재 대상으로 둘지는 PM 승인 대상이다.
  • 가정: 외주 인력 외부 접속 대상은 원칙적으로 dev 또는 staging 환경이며, 운영 환경 접속과 공개 IP 직접 개방은 PM/A7/A9 명시 승인 전 금지한다.
  • 가정: 외주 접속 환경에는 실데이터, 개인정보, 민감정보, 운영 시크릿을 노출하지 않고 샘플 데이터 또는 마스킹 데이터를 기본으로 사용한다.

인당 생산성/마진 기여: 불확실성을 가정으로 표시해 잘못된 전제 기반 구현과 폐기 비용을 줄인다.

D-A7-001 MVP 권한 모델은 RBAC를 기본으로 하고, 테넌트 범위와 업무 목적을 함께 평가한다. 초안 역할 기반 권한으로 온보딩과 권한 점검 시간을 줄이고 과도한 접근 사고 비용을 낮춘다.

D-A7-003 개인정보 상세 조회, 검색 노출, 다운로드, 마스킹 해제, 외부 전송은 개인정보 접근로그 대상이다. 초안 개인정보 감사 질의와 이상 접근 조사 시간을 단축한다.
D-A7-004 계약, 정산, 포인트, 승인, 권한, 외부 연동 재처리는 변경 전후 감사로그를 남긴다. 초안 외감 증적 수집과 정산 오류 조사에 투입되는 수작업을 줄인다.
D-A7-005 개인정보/민감정보 항목과 처리범위는 PM 승인 전 확정하지 않는다. PM 승인 필요 승인 없는 개인정보 설계로 인한 보안 재작업과 규제 리스크를 줄인다.
D-A7-006 로그 실패 시 개인정보 반출, 마스킹 해제, 권한 변경, 정산 확정은 실패 또는 보류한다. 초안 증적 누락 상태의 고위험 처리를 막아 사후 복구 비용을 줄인다.
D-A7-007 외감 대응 증적은 업무 이벤트와 회계/정산 참조 ID로 연결한다. 초안 월마감, 감사 샘플링, 분쟁 대응 시 자료 수집 시간을 줄인다.
D-A7-008 보존기간, 파기 방식, 로그 무결성 보장 방식은 정책 후보로만 두고 PM 승인 후 확정한다. PM 승인 필요 과도한 보관 비용과 불필요한 개인정보 보유 리스크를 동시에 낮춘다.

11.2 설정 메뉴 로그기록 확인 요구

항목 요구사항 인수조건
메뉴 위치 설정 메뉴 하위에 로그기록 메뉴를 둔다. 권한 없는 사용자는 메뉴와 API 모두 접근할 수 없어야 한다.
조회 필터 기간, 사용자, 대상 엔티티, 이벤트 유형, 권한, 고객, 상품, 주문 기준 필터를 제공한다. 최소 하나 이상의 필터 없이 대량 로그 전체 반출을 허용하지 않는다.
로그 범위 타임로그, 감사로그, 개인정보 접근로그를 목적별 탭 또는 필터로 구분한다. 개인정보 포함 로그는 기본 마스킹 또는 제한 조회되어야 한다.
정렬/추적 발생시각, 이벤트 유형, 대상, 사용자 기준 정렬을 지원한다. 고객정보/임직원정보/매출정보/상품정보 변경 건을 ID로 재조회할 수 있어야 한다.
상세 조회 변경 전후 참조, 승인 ID, 관련 업무 ID, 산식 버전, 발행 문서 ID를 보여준다. 상세 조회 자체도 접근로그 또는 감사로그 대상이어야 한다.
메뉴별 로그 메뉴명, 라우트, 이벤트 유형, 사용자, 권한, 결과, 대상 엔티티 기준으로 메뉴별 로그 탭을 제공한다. menu_opened, list_viewed, detail_viewed, created, updated, deleted, approved, rejected, on_hold, export_requested, filter_saved, permission_denied가 구분되어야 한다.
개인정보 마스킹 메뉴별 로그에 개인정보/임직원정보 필드 또는 검색 조건이 포함되면 기본 마스킹한다. 마스킹 해제 또는 반출은 승인 ID, 목적, 접근로그를 요구해야 한다.
비용 입력 로그 수익성 비용 입력 메뉴의 진입, 조회, 입력, 수정, 삭제, 권한 차단, 결재 요청 후보를 메뉴별 로그로 남긴다. 제원원가/판관비/일반관리비 변경 전후 값, 적용 범위, 적용일, 산식 버전, 변경 사유가 조회되어야 한다.

인당 생산성/마진 기여: 설정 메뉴에서 로그를 빠르게 찾게 해 운영, 재무, 보안 담당자의 원인 조사 시간을 줄인다.

11.3 외주 인력 외부 접속 보안 검토안

공개 IP 직접 개방은 로컬 개발 PC, 검증 서버, 운영 시스템, 소스, 개인정보, 운영 데이터 노출 위험이 커서 비권고한다. 외주 접속은 PM 승인, A7 보안 검토, A9 접속 환경 검토 후 dev 또는 staging 환경에 한정해 허용한다.

접속 방식 후보 보안 검토 권고 필수 통제 인당 생산성/마진 기여
VPN 계정 또는 외주 고정 IP 기반으로 검증망 접근 1순위 후보 개인별 계정, 만료일, MFA 후보, 접속로그, 최소권한 검수 지연을 줄이면서 접근 범위를 중앙에서 회수한다.
허용 IP 목록 외주 고정 IP만 dev/staging 접근 허용 2순위 후보 고정 IP 확인, 기간 제한, 메뉴별 로그, 다운로드 차단 구현 난이도를 낮추되 무단 위치 접근을 줄인다.
Zero Trust Access 계정, MFA, 정책 기반 웹 접근 2순위 후보 사용자/기기/위치 정책, 세션 로그, 만료일 외주별 접근 범위를 세밀하게 관리해 권한 점검 시간을 줄인다.
임시 터널 단기 검수용 임시 URL 긴급 검수 후보 짧은 만료, IP/계정 제한, 샘플 데이터, 접속 종료 후 회수 단기 검수 병목을 풀되 상시 노출을 방지한다.
공개 IP 직접 개방 서버/로컬 포트를 인터넷에 직접 노출 비권고 PM/A7/A9 명시 승인 없이는 금지 사고 대응과 보안 재작업 비용을 예방한다.
통제 항목 요구사항 인수조건
계정 외주 계정은 개인별로 발급하고 공유 계정을 금지한다. 외주 업체명, 담당자 이름/이메일, 접속 목적, 만료일이 기록되어야 한다.
인증 MFA 또는 이에 준하는 추가 인증을 후보로 둔다. MFA 적용 여부는 PM 승인 전 확정하지 않고 미적용 시 대체 통제를 기록한다.
권한 필요한 메뉴와 기능만 최소권한으로 부여한다. 권한 없는 메뉴 진입, 조회, 변경, 다운로드 시도는 permission_denied 로그로 남아야 한다.
데이터 개인정보와 운영 데이터는 마스킹 또는 샘플 데이터로 제공한다. 실데이터, 운영 시크릿, 개인정보 원문 노출은 기본 차단되어야 한다.
다운로드 다운로드/반출은 기본 차단한다. 예외 허용 시 승인 ID, 대상, 건수, 만료일, 사유가 감사로그에 남아야 한다.
로그 접속, 로그인 실패, 메뉴 진입, 조회, 변경, 결재, 반출 요청을 기록한다. 메뉴별 로그와 외주 접속 로그를 외주 사용자 ID로 조회할 수 있어야 한다.
회수 기간 종료 후 계정, 허용 IP, 터널, 정책을 회수한다. 만료 계정과 미회수 정책이 조회되어야 하며 회수 이력이 남아야 한다.

인당 생산성/마진 기여: 외주가 필요한 화면을 검수할 수 있게 하면서 과도한 노출과 계정 방치로 인한 사고 비용을 줄인다.

19. A1/A2/A4/A6/A8/A9 반영 체크리스트

19.1 A1 아키텍처

체크 요구사항 완료 기준
A1-C01 인증 사용자 기준으로 서버에서 tenant_scope를 계산한다. 클라이언트 전달 테넌트 값만으로 접근 허용하지 않는다.
A1-C02 모든 핵심 엔티티는 감사 메타데이터를 가진다. actor_id, tenant_scope, trace_id, 생성/수정 시각이 설계에 포함된다.
A1-C03 개인정보 원문 필드는 PM 승인 전 확정 모델에 넣지 않는다. 후보 필드와 승인 필요 항목이 분리되어 있다.
A1-C04 로그 저장과 업무 저장의 목적을 분리한다. 접근로그/감사로그 조회 권한과 업무 데이터 변경 권한이 분리된다.
A1-C05 유통 프로세스 상태머신은 타임로그와 감사로그 이벤트를 공통 발행한다. 영업활동부터 매출인식까지 주요 상태 변경 이벤트가 누락되지 않는다.
A1-C06 담당 배정과 결재 버튼 실행은 서버 권한 정책으로 평가한다. UI 버튼 숨김과 별개로 API 직접 호출 시 권한 없는 배정 변경과 결재 처리가 거부된다.
A1-C07 입사등록 최종 승인 전 계정 활성화와 권한 부여를 서버 상태전이에서 차단한다. approved 전에는 activated 또는 권한 부여 완료 상태로 전환될 수 없다.
A1-C08 수익성 비용 입력 API는 Master 또는 ProfitCostInputManager 후보 권한을 서버에서 검증한다. 권한 없는 제원원가/판관비/일반관리비 저장 요청은 차단되고 로그가 남는다.

인당 생산성/마진 기여: 공통 아키텍처에 통제를 심어 화면/API별 재구현과 보안 결함 비용을 줄인다.

19.2 A2 운영 콘솔

체크 요구사항 완료 기준
A2-C01 운영 업무 상세 조회는 역할, 배정, 테넌트, 목적을 평가한다. 타 고객사/공급사 업무 조회가 차단된다.
A2-C02 상태 변경, 배정, 보류, 완료, 반려는 감사로그를 남긴다. 변경 전후 상태와 사유가 재현 가능하다.
A2-C03 개인정보 포함 화면은 기본 마스킹을 적용한다. 마스킹 해제는 승인 ID와 접근로그를 요구한다.
A2-C04 금액/포인트/정산 보정은 승인 없이 완료할 수 없다. 승인 누락 시 보류 또는 실패 처리된다.
A2-C05 견적, 계약, 세금계산서/거래명세표, 매출인식 조정은 결재라인과 연결한다. 작성자, 결재자, 순서, 상태 변경 이력이 타임로그와 감사로그에 남는다.
A2-C06 고객정보, 임직원정보, 매출정보, 상품정보의 생성/수정/삭제/조회 이벤트를 로그 이벤트로 발행한다. 고객 수정 저장, 상품 판매가격 변경, 매출정보 수정, 임직원정보 조회가 로그로 남는다.
A2-C07 임직원-거래처 다대다 배정 화면은 배정 변경 권한, 거래처별 담당자 노출 범위, 저장 전 변경 확인을 적용한다. 배정 생성, 역할 변경, 대표 담당자 변경, 종료가 타임로그와 감사로그 후보로 남는다.
A2-C08 결재, 승인, 반려, 보류 버튼 의미와 결과 상태를 분리하고 반려/보류 사유를 필수화한다. 권한 없는 결재 버튼 실행은 차단되고 거부 로그가 남으며 보류 상태는 감사 증적으로 조회된다.
A2-C09 입사등록 승인상태는 결재문건 상태와 일치해야 하며 최종 승인 전 계정 활성화/권한 부여를 완료하지 않는다. 입사등록 생성, 수정, 상신, 승인, 반려, 보류, 활성화 대기/완료가 로그로 남는다.

인당 생산성/마진 기여: 운영 콘솔에서 증적을 자동 생성해 처리량을 높이고 수동 이력 정리를 줄인다.

19.3 A4 데이터/수익성/정산 모델

체크 요구사항 완료 기준
A4-C01 정산, 포인트, 수익성 지표는 원천 데이터와 계산 기준을 추적한다. source_system, source_record_id, 계산 버전 후보가 존재한다.
A4-C02 개인정보/민감정보 후보 필드는 승인 필요 목록으로 분리한다. 확정 모델에는 PM 승인 없는 원문 민감정보가 없다.
A4-C03 외감 대상 정산/포인트 이벤트는 감사로그와 연결된다. settlement_id, point_transaction_id, audit_id 연결이 가능하다.
A4-C04 대시보드는 기본 집계/비식별 지표를 사용한다. 상세 드릴다운은 별도 권한과 접근로그를 요구한다.
A4-C05 영업이익 산식 버전과 매출인식 기준을 데이터 모델에 분리한다. 산식 변경 전후와 적용 매출 레코드를 추적할 수 있다.
A4-C06 employee_customer_assignment 관계와 배정 이력 키를 데이터 모델 후보로 분리한다. 담당자 노출과 배정 변경 로그가 employee_account_id, customer_account_id, assignment_id로 연결된다.
A4-C07 입사등록 후보 정보와 활성 임직원 계정/권한 정보를 상태와 승인 ID로 분리한다. 승인 전 후보 정보가 활성 계정 또는 권한 완료 데이터로 오인되지 않는다.
A4-C08 비용 입력 값은 산식 버전, 적용 범위, 적용일, 변경 전후 참조로 관리한다. 영업이익 대시보드가 어떤 비용 입력 버전을 사용했는지 추적 가능하다.

인당 생산성/마진 기여: 지표와 증적의 원천 추적성을 확보해 수기 검산과 대시보드 불신 비용을 줄인다.

19.4 A6 통합/연동

체크 요구사항 완료 기준
A6-C01 외부 전송 항목은 연동별로 목적과 항목을 문서화한다. 개인정보 전송 항목은 PM 승인 필요로 표시된다.
A6-C02 모든 쓰기성 연동은 idempotency_key를 가진다. 중복 요청이 중복 지급/취소/정산으로 이어지지 않는다.
A6-C03 외부 요청/응답/재시도/수동 보정은 감사로그 대상이다. 요청 ID와 재처리 이력이 추적 가능하다.
A6-C04 연동 원문 저장은 마스킹 기본이며 원문 보관은 승인 필요다. 원문 보관 여부가 임의 구현되지 않는다.
A6-C05 택배사, 세금계산서/거래명세표 외부 연동 후보는 실패 큐와 수동 보정 경로를 가진다. 실시간 위치 조회 실패, 발행 실패, 재발행 이력이 감사 가능해야 한다.

인당 생산성/마진 기여: 연동 실패와 중복 처리로 인한 운영 보정 시간을 줄이고 금전 손실을 예방한다.

19.5 A8 QA

체크 요구사항 완료 기준
A8-C01 RBAC, 테넌트 격리, 접근로그, 감사로그 테스트를 P0 통과 조건에 포함한다. 권한 우회, 로그 누락 기능은 반려된다.
A8-C02 정산/포인트/연동 멱등성 테스트를 포함한다. 재실행 시 중복 금전 변동이 없어야 한다.
A8-C03 개인정보 처리 테스트는 비식별 샘플 데이터로 수행한다. 실데이터 사용은 PM 승인 전 금지된다.
A8-C04 외감 증적 샘플 조회 테스트를 포함한다. 기간, 거래, 승인, 변경 이력 기준 샘플 조회가 가능해야 한다.
A8-C05 권한별 메뉴, 결재라인, 영업이익 산식, 타임로그 검증을 포함한다. 일반/관리자/슈퍼바이저 권한별 화면과 API 결과가 일치해야 한다.
A8-C06 설정 메뉴 로그기록 조회 권한과 필터/정렬/상세 조회를 검증한다. 권한 없는 사용자는 로그 상세를 볼 수 없고 개인정보 포함 로그는 마스킹되어야 한다.
A8-C07 담당자 배정 변경과 거래처별 담당자 노출 권한을 검증한다. 권한 없는 사용자는 배정 변경 저장이 실패하고 담당자 개인정보 필드는 승인 범위 밖에서 노출되지 않는다.
A8-C08 승인/반려/보류 버튼 권한, 사유 필수, 보류 상태 증적을 검증한다. 현재 결재자가 아닌 사용자의 처리와 사유 없는 반려/보류는 실패해야 한다.
A8-C09 입사등록 최종 승인 전 계정 활성화/권한 부여 차단과 메뉴별 로그 마스킹을 검증한다. 승인 전 활성화 시도는 실패하고 메뉴별 개인정보 로그는 기본 마스킹되어야 한다.
A8-C10 수익성 비용 입력 권한, 권한 부여/회수 로그, 변경 전후 감사로그, 권한 없는 접근 차단을 검증한다. 일반/관리자는 비용 입력 저장이 실패하고 Master 또는 입력 권한자 변경만 감사로그로 남아야 한다.
A8-C11 외주 접속 권한, 데이터 마스킹, 다운로드 차단, 메뉴별 로그, 만료 회수를 검증한다. 외주 계정은 승인된 dev/staging 메뉴만 접근하고 개인정보 원문과 다운로드는 차단되어야 한다.

인당 생산성/마진 기여: 보안·감사 결함을 릴리즈 전에 차단해 운영 전환 후 재처리와 장애 대응 비용을 줄인다.

19.6 A9 DevOps

체크 요구사항 완료 기준
A9-C01 접근로그/감사로그는 무결성, 검색성, 보존정책 후보를 가진다. 로그 삭제/변조 방지 방식은 PM 승인 필요로 관리된다.
A9-C02 시크릿, 키, 인증서 접근과 변경은 감사 대상이다. 시크릿 노출이 로그/문서/코드에 남지 않는다.
A9-C03 배포, 롤백, 설정 변경은 변경 이력으로 기록한다. 커밋 SHA, 승인자, 배포자, 시간, 결과가 남는다.
A9-C04 로그 실패 모니터링과 알림 기준을 둔다. 고위험 작업 로그 실패는 실패 또는 보류된다.
A9-C05 타임로그와 감사로그는 검색, 무결성, 보존정책 후보를 가진다. 세금계산서/매출인식/산식 변경 증적을 기간과 ID로 조회할 수 있어야 한다.
A9-C06 로그기록 메뉴 조회 자체를 접근로그 또는 감사로그로 남긴다. 로그 조회자, 필터, 대상, 결과 수가 추적되어야 한다.
A9-C07 담당 배정 변경, 권한 없는 결재 버튼 실행, 보류 상태 변경 로그를 검색 가능하게 보관한다. assignment_id, approval_id, actor_user_id, result로 로그를 조회할 수 있어야 한다.
A9-C08 메뉴별 로그와 입사등록 결재/활성화 로그는 보존정책 후보와 접근권한을 가진다. menu_id, onboarding_id, approval_id, actor_user_id로 검색 가능하고 반출 권한이 분리된다.
A9-C09 비용 입력 권한 부여/회수와 비용 변경 로그는 무결성, 검색성, 보존정책 후보를 가진다. cost_input_id, profit_formula_version, actor_user_id, result로 조회 가능해야 한다.
A9-C10 외주 접속 방식은 공개 IP 직접 개방을 피하고 승인된 VPN/허용 IP/Zero Trust/임시 터널 후보로 관리한다. 개인별 계정, 만료일, 접속로그, 메뉴별 로그, 권한 회수 이력이 있어야 한다.

인당 생산성/마진 기여: 운영 증적과 장애 추적성을 높여 배포 실패, 감사 대응, 사고 조사 시간을 줄인다.
