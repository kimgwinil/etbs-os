# Security & Audit Baseline

## 1. 목적

이 스펙은 이제너두 전사 CRM OS MVP의 컴플라이언스·보안·감사 구현 기준선이다. A1/A2/A4/A6/A8/A9가 RBAC, 테넌트 격리, 개인정보 접근로그, 감사로그, 보존정책, 외감 증적 요구를 구현 또는 검증할 때 사용할 공통 요구사항을 정의한다.

개인정보/민감정보 항목, 처리범위, 보관기간, 외부 전송 항목, 위탁/재위탁, 최종 아키텍처는 본 스펙에서 확정하지 않으며 모두 PM 승인 필요로 둔다.

인당 생산성/마진 기여: 검증 가능한 기준선을 제공해 보안 요구 누락, 감사 증적 재수집, 권한 재작업에 들어가는 반복 인력을 줄인다.

## 5. 공통 원칙

| 원칙 ID | 원칙 | 요구사항 | 인당 생산성/마진 기여 |
|---|---|---|---|
| `SEC-01` | 최소권한 | 사용자는 업무 수행에 필요한 최소 역할과 테넌트 범위만 가진다. | 권한 정리와 사고 조사 비용을 줄인다. |
| `SEC-02` | 서버 기준 테넌트 평가 | API는 클라이언트 입력이 아니라 인증 사용자와 정책으로 허용 범위를 계산한다. | 화면/API별 권한 누락을 줄인다. |
| `SEC-03` | 로그 우선 설계 | 개인정보 접근과 주요 변경은 기능 릴리스 전 로그 요건을 충족해야 한다. | 사후 증적 복구와 감사 대응 시간을 줄인다. |
| `SEC-04` | 승인 게이트 | 개인정보, 민감정보, 반출, 외부 전송, 보존기간은 PM 승인 전 확정 금지다. | 승인 없는 과잉 구현과 폐기 비용을 줄인다. |
| `SEC-05` | 고위험 작업 로그 실패 차단 | 로그 실패 시 반출, 마스킹 해제, 권한 변경, 정산 확정은 실패 또는 보류한다. | 증적 누락 상태의 금전/개인정보 리스크를 예방한다. |
| `SEC-06` | 외감 추적성 | 정산, 포인트, 승인, 변경 이벤트는 원천 ID와 감사 ID로 연결한다. | 월마감과 외감 샘플 대응 시간을 줄인다. |
| `SEC-07` | 프로세스 타임로그 | 영업활동부터 매출인식까지 생성, 수정, 삭제, 승인, 상태 변경, 발행, 조회 이력을 남긴다. | 단계별 병목과 책임소재 확인 시간을 줄인다. |
| `SEC-08` | 권한별 메뉴/API 일치 | 일반 직원, 관리자, 슈퍼바이저 메뉴 노출과 API 권한을 같은 정책으로 평가한다. | 불필요한 메뉴 노출과 권한 우회 결함을 줄인다. |
| `SEC-09` | 로그기록 조회 통제 | 설정 메뉴 `로그기록` 조회 자체도 접근 이력으로 남기고 권한별 조회 범위를 제한한다. | 로그를 빠르게 찾되 로그를 통한 정보 노출을 막는다. |
| `SEC-10` | 담당 배정 최소권한 | 임직원-거래처 담당 배정 생성, 변경, 종료, 대표 담당자 변경은 승인된 역할만 수행한다. | 담당자 공백과 오배정으로 생기는 문의·인수인계 시간을 줄인다. |
| `SEC-11` | 결재 버튼 서버 검증 | 결재, 승인, 반려, 보류 버튼은 현재 결재자와 역할을 서버에서 검증하고 사유와 결과를 로그로 남긴다. | 결재 오처리와 재상신 비용을 줄이고 발행·매출 지연을 낮춘다. |
| `SEC-12` | 입사등록 승인 게이트 | 입사등록 최종 승인 전 임직원 계정 활성화와 권한 부여를 완료하지 않는다. | 승인 없는 계정 생성과 권한 오부여 재작업을 줄인다. |
| `SEC-13` | 메뉴별 로그 기본 마스킹 | 메뉴별 로그는 메뉴 진입, 조회, 수정, 결재, 반출을 기록하고 개인정보 포함 값은 기본 마스킹한다. | 메뉴 단위 권한 점검과 장애 조사 시간을 줄인다. |
| `SEC-14` | 수익성 비용 입력 최소권한 | 제원원가, 판관비, 일반관리비 입력은 `Master` 또는 `ProfitCostInputManager` 후보 권한으로 제한한다. | 영업이익 지표 왜곡과 재검산 시간을 줄인다. |
| `SEC-15` | 외주 접속 제한 | 외주 인력 접속은 공개 IP 직접 개방을 비권고로 두고 승인된 VPN, 허용 IP, Zero Trust, 만료형 임시 터널 후보만 허용한다. | 외주 검수 지연을 줄이면서 노출 사고와 계정 방치 비용을 예방한다. |

## 11. 개인정보 흐름도

```text
고객사/공급사/임직원/레거시 입력
  -> CRM Core
     -> Operations Console
        -> 업무/CS 이력
        -> 개인정보 접근로그
     -> Settlement & Point Ops
        -> 포인트 원장
        -> 정산/회계 증적
        -> 감사로그
     -> Integration Hub
        -> 베네카페/결제/온누리/공급사 API
        -> 개인정보 접근로그
        -> 감사로그
     -> Sales Process
        -> 영업활동/파이프라인/견적/계약/주문/출고/배송
        -> 세금계산서/거래명세표
        -> 매출인식/영업이익 산식
        -> 결재라인/타임로그/감사로그
     -> Profitability Dashboard
        -> 집계/비식별 지표/슈퍼바이저 대시보드
```

|---|---|---|

| `AC-06` | 개인정보 흐름도와 위험-통제 매핑이 최신 스펙에 포함되어야 한다. |
| `AC-07` | 민감정보 항목과 처리범위는 확정하지 않고 `PM 승인 필요`로 표시되어야 한다. |
| `AC-08` | 보존기간, 파기 방식, 외부 전송 항목은 PM 승인 전 확정하지 않아야 한다. |
| `AC-09` | 외감 대응을 위한 정산, 포인트, 승인, 변경 이력 증적 요구사항이 포함되어야 한다. |
| `AC-10` | A1/A2/A4/A6/A8/A9 체크리스트가 존재해야 한다. |
| `AC-11` | 임직원정보, 권한별 메뉴, 슈퍼바이저 대시보드 접근 통제가 존재해야 한다. |
| `AC-12` | 결재라인, 세금계산서/거래명세표, 매출인식, 영업이익 산식 변경 증적 요구사항이 존재해야 한다. |
| `AC-13` | 영업활동부터 매출인식까지 타임로그와 감사로그 요구사항이 존재해야 한다. |
| `AC-14` | 고객정보, 임직원정보, 매출정보, 상품정보의 타임로그/감사로그 대상과 필수 연결 키가 존재해야 한다. |
| `AC-15` | 설정 메뉴 `로그기록` 확인 메뉴의 권한, 필터, 정렬, 상세 조회, 마스킹 인수조건이 존재해야 한다. |
| `AC-16` | 임직원-거래처 다대다 배정의 변경 권한, 담당자 노출 범위, 배정 변경 타임로그 요구가 존재해야 한다. |
| `AC-17` | 결재/승인/반려/보류 버튼 의미, 권한 없는 처리 차단, 사유 로그, 보류 상태 감사 증적 요구가 존재해야 한다. |
| `AC-18` | 입사등록 승인 전 임직원 계정 활성화/권한 부여 금지와 처리범위 승인 게이트가 존재해야 한다. |
| `AC-19` | 메뉴별 로그의 개인정보 마스킹, 메뉴 진입/조회/수정/결재/반출 로그 보존 및 접근권한 요구가 존재해야 한다. |
| `AC-20` | 제원원가/판관비/일반관리비 입력 권한 제한, 권한 부여/회수 로그, 비용 변경 전후 감사로그, 권한 없는 접근 차단, 결재 대상 여부 PM 승인 항목이 존재해야 한다. |
| `AC-21` | 외주 인력 외부 접속 보안 검토안에 공개 IP 직접 개방 비권고, 접속 방식 후보 비교, 개인별 계정, 만료일, MFA 후보, 메뉴별 로그, 다운로드 차단, 개인정보/운영 데이터 마스킹이 존재해야 한다. |

인당 생산성/마진 기여: 명확한 인수조건으로 보안 검증을 자동화 후보로 만들고 반복 검토 시간을 줄인다.

## 17. 의존성 및 PM 승인 필요 항목

| 의존성 | 필요 내용 | 상태 |
|---|---|---|
| 1. 개인정보/임직원정보 접근 범위 | 개인정보, 민감정보, 임직원 신상명세/인적사항, 입사등록 개인정보/임직원정보 처리범위, 외주 접속 데이터 조회/마스킹 범위, 거래처별 담당자 노출 필드, 담당 배정 변경 권한, 슈퍼바이저 드릴다운, 반출/마스킹 해제 범위 | PM 승인 필요 |
| 2. 회계/세무/외감 기준 | 세금계산서/거래명세표 발행 기준, 매출인식 기준, 영업이익 MVP 산식, 제원원가/판관비/일반관리비 의미와 결재 대상 여부, 증적 제출 범위와 보존기간 | PM 승인 필요 |
| 3. 외부연동/보안운영 기준 | 택배사·전자문서·결제/온누리/베네카페 연동 범위, 외주 접속 방식과 대상 환경, 위탁/재위탁, 로그 저장·무결성·암호화·키 운영 방식, 결재 보류 상태 로그 운영 기준, 메뉴별 로그 보존/반출 권한 | PM 승인 필요 |

문중의 세부 `PM 승인 필요` 표기는 위 3개 항목 중 하나에 매핑한다.

인당 생산성/마진 기여: 승인 항목을 3개 범주로 압축해 의사결정 병목을 줄이고 MVP 구현팀이 불확실한 영역을 임의 확정하지 않게 한다.

## 18. KPI 영향

| KPI | 측정 방향 |
|---|---|
| 권한 요청 처리시간 | 역할 기반 승인 흐름 도입 전후 비교 |

| 결재 대기/누락 건수 | 결재라인 시스템화 전후 비교 |
| 이익 저하 원인 식별 시간 | 슈퍼바이저 대시보드에서 원인 후보 확인까지 소요시간 |
| 포인트 수동 보정 건수 | 멱등성/원장 이벤트 도입 전후 비교 |
| 운영자 1인당 처리 건수 | 권한 확인/증적 수집 자동화 후 처리량 |
| 보안 재작업 건수 | MVP 이후 보안 보완 이슈 수 |

인당 생산성/마진 기여: 보안 스펙을 경영 KPI에 연결해 통제를 운영 효율과 리스크 비용 절감 수단으로 관리한다.
