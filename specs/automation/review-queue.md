# Automation Review Queue 스펙

## 1. 목적

Automation Review Queue는 Automation/RPA Workbench가 자동 처리하지 못한 업무를 P0 Operations Console의 표준 큐로 넘기고, 사람이 검토·반려·보류·재처리할 수 있도록 판단 기준, 상태 전이, 입력/출력, KPI 측정 기준을 정의한다.

본 스펙은 민감정보 처리범위를 확정하지 않는다. 의료비, 학자금, 첨부 증빙, 가족관계, 건강정보 가능 데이터는 PM 김권일 승인 전 구체 항목과 자동 분석 범위를 확정하지 않는다.

인당 생산성/마진 기여: 예외 업무를 표준 큐로 정리해 담당자가 원인을 다시 찾는 시간을 줄이고 자동화 실패가 곧 운영 병목으로 돌아오지 않게 한다.

## 2. 큐 입력과 출력

| 구분 | 항목 | 설명 |
|---|---|---|
| 입력 | `work_item_id` | Operations Console의 표준 업무 ID |
| 입력 | `automation_run_id` | 자동화 실행 ID |
| 입력 | `business_type` | `cs`, `point`, `settlement`, `medical_expense`, `tuition`, `approval_alert`, `delivery_exception`, `shipment_delay`, `tax_invoice`, `trade_statement`, `profit_drop`, `log_anomaly` 등 업무유형 |
| 입력 | `tenant_id` | 고객사 또는 테넌트 식별자 |
| 입력 | `subject_ref` | 임직원, 공급사, 거래 등 대상 참조 ID |
| 입력 | `risk_flags` | 금액, 개인정보, 정책 충돌, 중복, 연동 실패, 결재 지연, 출고 지연, 배송 예외, 발행 누락, 이익 저하, 로그 이상징후 등 위험 플래그 |
| 입력 | `rule_results` | 적용 규칙, 통과/실패 결과, 규칙 버전 |
| 입력 | `evidence_refs` | 원천 파일, API 요청, 거래, 첨부파일 메타데이터 참조 |
| 출력 | `queue_status` | `needs_review`, `approved`, `rejected`, `on_hold`, `retry_pending`, `completed` |
| 출력 | `decision_code` | 표준 결정 사유 코드 |
| 출력 | `decision_note` | 내부 검토 메모 |
| 출력 | `user_message_code` | 사용자 또는 고객사 표시 문구 코드 |
| 출력 | `next_action_at` | 보류 해제, 재처리, SLA 알림 기준 시각 |

결정: 큐에는 원천 민감정보 본문을 직접 복제하지 않고 참조 ID와 메타데이터 중심으로 연결한다.

인당 생산성/마진 기여: 데이터 중복과 접근 통제 비용을 줄이면서 검토자가 필요한 원천으로 빠르게 이동하게 한다.

## 3. 상태 전이

| 현재 상태 | 트리거 | 다음 상태 | 조건 |
|---|---|---|---|
| `received` | 자동화 규칙 전체 통과 | `completed` | 자동 처리 허용 업무이고 리스크 플래그가 없음 |
| `received` | 자동화 규칙 일부 실패 | `needs_review` | 정책 충돌, 중복 의심, 금액 초과, 민감정보 가능성 |
| `received` | 외부 데이터 지연 또는 승인 대기 | `on_hold` | 원천 데이터 미도착, PM 승인 필요, 고객사 정책 미확정 |
| `received` | 결재 SLA 초과 또는 배송/출고 SLA 초과 | `needs_review` | 결재 지연, 미출고, 배송 지연, 반송, 오배송 |
| `received` | 발행 필수값 누락 또는 중복 발행 의심 | `needs_review` | 사업자번호, 공급가, 세액, 결재 상태, 기존 발행 이력 불일치 |
| `received` | 이익 저하 또는 로그 이상징후 탐지 | `needs_review` | 할인/반품/배송비/처리시간/정산 지연 이상, 권한·조회·수정 패턴 이상 |
| `needs_review` | 담당자 승인 | `approved` | 검토자가 증빙과 정책을 확인함 |
| `needs_review` | 담당자 반려 | `rejected` | 보완으로 해결 불가하거나 정책상 불가 |
| `needs_review` | 담당자 보완 요청 | `on_hold` | 사용자/고객사/공급사 추가 입력 필요 |
| `needs_review` | 일시 오류 재시도 가능 | `retry_pending` | 멱등 키가 있고 재처리 제한 횟수 미만 |
| `retry_pending` | 재처리 성공 | `completed` | 외부 시스템 반영 또는 대사 성공 |
| `retry_pending` | 재처리 실패 한도 초과 | `needs_review` | 사람 확인 필요 |
| `approved` | 후속 시스템 반영 성공 | `completed` | 포인트/정산/CS 후속 상태 반영 완료 |

결정: `completed`는 자동 또는 사람 승인 이후 후속 시스템 반영이 끝난 상태로만 사용한다.

인당 생산성/마진 기여: 완료 기준을 엄격히 해 미반영 건 재확인과 고객사 문의 대응 시간을 줄인다.

## 4. 자동 처리 기준

자동 처리는 다음 조건을 모두 충족할 때만 허용한다.

| 기준 | 요구사항 |
|---|---|
| 필수 입력 | 업무유형별 필수 필드가 모두 존재한다 |
| 정책 일치 | 고객사 정책, 기간, 한도, 대상자 조건이 모두 일치한다 |
| 권한 일치 | 요청자와 승인자의 역할이 허용 범위에 있다 |
| 중복 없음 | 업무유형별 중복 키가 기존 완료/진행 건과 충돌하지 않는다 |
| 금액 리스크 | PM 승인 또는 운영 정책에서 정한 자동 처리 한도 이내다 |
| 민감정보 범위 | PM 승인된 처리범위 안에서만 자동 판단한다 |
| 연동 안정성 | 후속 시스템이 멱등 키와 결과 조회를 지원한다 |
| 감사 가능성 | 적용 규칙 버전, 입력 참조, 결과 이벤트가 저장된다 |

결정: 위 조건 중 하나라도 불충족하면 자동 완료하지 않고 사람 검토, 보류, 재처리 중 하나로 전환한다.

인당 생산성/마진 기여: 자동화 오류를 줄여 보정·환불·고객사 신뢰 손실 비용을 막는다.

## 5. 사람 검토 기준

| 검토 사유 | 큐 진입 기준 | 기본 담당 |
|---|---|---|
| 금액 리스크 | 자동 처리 한도 초과, 정산 차이, 포인트 잔액 부족 | 운영/정산 담당 |
| 정책 충돌 | 고객사 정책 누락, 기간/대상/한도 불일치 | 운영 담당 |
| 개인정보 리스크 | 민감정보 가능 첨부, 가족관계/건강정보 가능 항목 | 개인정보 승인 담당 또는 지정 검토자 |
| 중복 의심 | 동일 대상·금액·기간·사유의 기존 건 존재 | 운영 담당 |
| 권한 불일치 | 요청자/승인자 권한 없음 또는 위임 미확인 | 운영 관리자 |
| 외부 연동 불일치 | 원장, 결제, 정산, 공급사 데이터 상태 불일치 | 연동/정산 담당 |
| VIP/고위험 고객사 | 별도 SLA 또는 수동 승인 정책 대상 | 전담 AM 또는 운영 관리자 |
| 결재 지연 | 결재 SLA 초과, 결재 라인 누락, 최종 결재자 미지정 | 결재 문건 담당자 또는 운영 관리자 |
| 배송/출고 예외 | 납기 초과, 미출고, 송장 누락, 반송, 오배송, 택배사 조회 실패 | 물류/운영 담당 |
| 발행 예외 | 세금계산서/거래명세표 필수값 누락, 금액 불일치, 중복 발행 의심 | 회계/운영 담당 |
| 이익 저하 | 할인, 반품, 배송비, 처리시간, 결재 지연, 정산 지연, 예외 건수 급증 | 슈퍼바이저 또는 수익성 담당 |
| 로그 이상징후 | 대량 수정/삭제, 야간 고위험 작업, 반복 실패, 비정상 조회 패턴 | 보안/감사 담당 |

결정: 사람 검토 큐는 단순 선입선출이 아니라 SLA, 금액 리스크, 고객사 중요도, 보류 경과시간을 기준으로 정렬한다.

인당 생산성/마진 기여: 고비용 리스크 건을 먼저 처리해 장애 확산과 고객사 이탈 가능성을 낮춘다.

## 6. 반려 기준

| 반려 코드 | 기준 | 사용자 표시 방향 |
|---|---|---|
| `POLICY_NOT_ELIGIBLE` | 고객사 정책상 대상자가 아님 | 정책상 신청 대상이 아님 |
| `PERIOD_OUT_OF_RANGE` | 신청 기간 또는 정산 기간이 허용 범위를 벗어남 | 신청 가능 기간을 벗어남 |
| `LIMIT_EXCEEDED_FINAL` | 한도 초과가 명확하고 예외 승인 없음 | 사용 가능 한도를 초과함 |
| `DUPLICATE_CONFIRMED` | 동일 건이 이미 처리됨 | 동일 신청이 이미 처리됨 |
| `UNAUTHORIZED_REQUEST` | 요청자 또는 승인자 권한 없음 | 처리 권한 확인이 필요함 |
| `INVALID_EVIDENCE_FINAL` | 보완 후에도 증빙이 유효하지 않음 | 제출 자료가 기준에 맞지 않음 |
| `INVALID_BILLING_PROFILE` | 사업자번호, 거래처, 세액 정보가 유효하지 않음 | 발행 정보 확인이 필요함 |
| `DUPLICATE_ISSUANCE_CONFIRMED` | 세금계산서/거래명세표가 이미 발행됨 | 동일 문서가 이미 발행됨 |
| `SHIPMENT_CANCELLED_OR_INVALID` | 출고 또는 배송 요청이 취소/무효 상태임 | 출고 또는 배송 상태 확인이 필요함 |

결정: 자동 반려는 PM 승인된 업무유형과 사유 코드에만 허용하고, 의료비·학자금은 PM 승인 전 자동 반려하지 않는다.

인당 생산성/마진 기여: 명확한 불가 건을 빠르게 종료하되 고위험 업무의 잘못된 반려로 생기는 재문의와 신뢰 손실을 줄인다.

## 7. 보류 기준

| 보류 코드 | 기준 | 해제 조건 |
|---|---|---|
| `WAITING_FOR_USER_INPUT` | 사용자 보완 자료 필요 | 보완 자료 접수 또는 기한 만료 |
| `WAITING_FOR_TENANT_POLICY` | 고객사 정책 미확정 | 정책 관리자 확인 |
| `WAITING_FOR_SOURCE_DATA` | 원천 거래/정산/포인트 데이터 지연 | 원천 데이터 수신 |
| `WAITING_FOR_PM_APPROVAL` | 개인정보, 민감정보, 예산, 외부계약 승인 필요 | PM 김권일 승인 |
| `WAITING_FOR_VENDOR_RESPONSE` | 공급사 또는 외부 시스템 확인 필요 | 응답 수신 또는 SLA 초과 |
| `WAITING_FOR_APPROVER` | 결재권자 승인 또는 결재 라인 수정 필요 | 결재 완료 또는 결재 라인 보정 |
| `WAITING_FOR_CARRIER_DATA` | 택배사 배송 상태 또는 송장 데이터 지연 | 배송 상태 수신 또는 수동 보정 |
| `WAITING_FOR_BILLING_CONFIRMATION` | 발행 전 회계/결재 확인 필요 | 회계/결재 확인 완료 |

결정: 보류 상태는 반드시 해제 조건과 다음 확인 시각을 가진다.

인당 생산성/마진 기여: 무기한 대기 건을 줄이고 운영자가 매번 보류 사유를 다시 파악하는 시간을 줄인다.

## 8. 재처리 기준

재처리는 일시적 실패이고 멱등 처리가 가능한 경우에만 허용한다.

| 기준 | 요구사항 |
|---|---|
| 멱등 키 | 동일 요청의 중복 반영을 막는 키가 있어야 한다 |
| 실패 유형 | 타임아웃, 일시적 5xx, 외부 큐 지연 등 재시도 가능 오류여야 한다 |
| 제한 횟수 | 업무유형별 최대 재시도 횟수와 간격이 있어야 한다 |
| 결과 확인 | 재시도 후 원장 또는 외부 상태 조회가 가능해야 한다 |
| 실패 이관 | 제한 횟수 초과 시 사람 검토 큐로 이동해야 한다 |

결정: 금액 반영 업무의 재처리는 원장 결과 조회가 불가능하면 자동 재처리하지 않는다.

인당 생산성/마진 기여: 중복 지급·중복 차감 같은 금전 오류를 방지해 보정 비용과 고객사 클레임을 줄인다.

결정: 배송 상태 재조회와 세금계산서/거래명세표 전송 실패는 멱등 키 또는 외부 문서 ID가 있을 때만 자동 재처리한다.

인당 생산성/마진 기여: 중복 발행과 잘못된 배송 상태 반영을 막아 회계 보정과 고객 문의 대응 시간을 줄인다.

| 업무유형 | 자동 처리 가능 | 기본 사람 검토 | 자동 반려 | 보류 | 재처리 |
|---|---|---|---|---|---|
| CS 분류 | 카테고리/담당 큐 자동 배정 | 개인정보/법무/정산/VIP 키워드 | 스팸·중복 문의 등 승인된 범위 | 채널 원문 지연 | 채널 연동 실패 |
| 포인트 | 한도·권한·중복 통과 건 | 잔액 부족, 대량 오류, 권한 불일치 | 명확한 중복 또는 정책 불가 | 원장 지연, 승인 대기 | 원장 반영 일시 실패 |
| 정산 | 대사 일치 건 | 금액 차이, 상태 불일치, 공급사 이의 | 확정 불가 데이터 제외 건 | 원천 데이터 미도착 | 대사/상태 조회 일시 실패 |

## 11. 인수조건

- 큐에 진입한 모든 건은 `work_item_id`, `business_type`, `queue_status`, `risk_flags`, `decision_code` 중 필요한 값을 가진다.
- 자동화 실행 결과는 Operations Console에서 사람이 확인하고 수정할 수 있다.
- 사람 검토자는 자동화가 실패한 규칙과 원천 참조를 볼 수 있다.
- 반려, 보류, 재처리 결정은 표준 코드와 내부 메모를 함께 저장한다.
- 보류 건은 해제 조건과 다음 확인 시각이 없으면 저장할 수 없다.
- 재처리 건은 멱등 키와 재시도 횟수 없이 실행할 수 없다.
- 민감정보 가능 업무는 PM 승인 전 자동 본문 분석, 자동 승인, 자동 반려를 확정하지 않는다.
- KPI는 업무유형, 고객사, 담당팀, 기간별로 집계 가능해야 한다.
- 결재 알림, 배송 예외, 출고 지연, 세금계산서/거래명세표 반복 발행, 영업이익 저하 원인 탐지, 로그 기반 이상징후 탐지는 자동화율, 평균 처리시간, 예외율을 반드시 산출해야 한다.

결정: 예외 큐는 운영자가 "왜 자동 처리되지 않았는지"를 한 화면에서 확인할 수 있어야 한다.

인당 생산성/마진 기여: 예외 원인 탐색 시간을 줄여 자동화 실패 건도 빠르게 처리하게 한다.
