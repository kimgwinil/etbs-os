# 외주 인력 외부 접속 환경 설계안

## 1. 목적

외주 인력이 외부 인터넷 환경에서 이제너두 전사 CRM OS의 개발/검증 대상 시스템에 접속할 수 있도록 하되, 운영 시스템, 운영 데이터, 개인정보, 소스, 시크릿이 노출되지 않도록 접속 환경, 계정, 로그, 차단 절차를 정의한다.

본 문서는 설계안이며 서버, 포트, 방화벽, 터널, VPN, DNS, 클라우드 네트워크 설정을 직접 수행하지 않는다. 특정 VPN, Zero Trust, 터널, WAF, Bastion, 관측성, 로그 보관 상용 도구는 PM 승인 필요 항목으로 분리한다.

인당 생산성/마진 기여: 외주 검수와 협업 지연을 줄이면서 보안 사고, 운영 중단, 감사 대응 비용을 예방한다.

## 2. 기준 입력

| 입력 | 설명 |
|---|---|
| `/docs/PRD.md` | MVP P0 모듈, 보안/감사 요구 |
| `/docs/PROCESS_REQUIREMENTS.md` | 권한별 메뉴 차등, 로그기록 메뉴, 운영 데이터 통제 |
| `/specs/audit/menu-log-records.md` | 메뉴별 로그 필드와 이벤트 |
| `/specs/audit/timelog-auditlog.md` | 타임로그/감사로그, 로그 조회 자체 감사 기준 |
| `/specs/devops/mvp-delivery-observability.md` | 환경 분리, 로그/메트릭/알림, 감사 증적 기준 |

인당 생산성/마진 기여: 기준 문서를 연결해 외주 접속이 별도 예외 운영이 아니라 기존 권한/로그/관측성 체계 안에서 통제되게 한다.

## 3. 기본 원칙

| 원칙 | 기준 |
|---|---|
| No Direct Exposure | 로컬 개발 PC, 운영 서버, 운영 DB, 운영 관리자 화면을 공개 인터넷에 직접 노출하지 않는다. |
| Dev/Staging Only | 외주 접속 대상은 원칙적으로 `dev` 또는 `staging`으로 제한한다. |
| No Production Data | 운영 데이터, 개인정보, 민감정보, 운영 시크릿, 운영 결제/정산/배송 연동 키는 외주 접속 환경에 노출하지 않는다. |
| Least Privilege | 외주 계정은 개인별, 목적별, 기간별 최소권한만 부여한다. |
| Expire by Default | 모든 외주 계정, 허용 IP, 터널, 접근 정책은 만료일을 가진다. |
| Log Everything | 접속, 인증 실패, 메뉴 진입, 조회, 변경, 다운로드 시도, 권한 차단을 로그로 남긴다. |
| Block Download by Default | CSV/Excel/API/첨부 다운로드와 운영 데이터 반출은 기본 차단한다. |
| PM Gate | 접속 방식, 기간, 권한, 데이터 범위, 상용 도구 도입은 PM 승인 후 확정한다. |

인당 생산성/마진 기여: 외주 접속을 빠르게 열되 권한과 데이터 노출을 기본 차단해 사고 대응 비용을 줄인다.

## 4. 접속 범위

| 환경 | 외주 접속 허용 | 데이터 기준 | 비고 |
|---|---|---|---|
| local | 금지 | 개발자 개인 환경 | 로컬 PC 공개 금지 |
| dev | 조건부 허용 | 샘플/더미/비식별 데이터 | 기능 확인과 개발 협업 |
| staging | 조건부 허용 | 마스킹된 운영 유사 데이터 후보 | UAT/검수, PM/A7 승인 필요 |
| prod | 원칙 금지 | 운영 데이터 | 예외 접속은 별도 PM/A7/A9 승인과 감사로그 필수 |

결정: 외주 접속은 `dev` 또는 `staging`으로 제한하고 `prod` 접속은 본 설계안의 기본 범위에서 제외한다.

인당 생산성/마진 기여: 운영 장애와 데이터 사고 가능성을 줄이면서 검수 가능한 환경을 유지한다.

PM 승인 필요: staging 데이터 마스킹 범위, prod 예외 접속 허용 여부, 외주가 볼 수 있는 메뉴와 데이터 범위.

## 5. 접속 방식 후보

| 방식 | 설명 | 장점 | 리스크/제약 | 권고 |
|---|---|---|---|---|
| VPN | 외주 개인 계정과 MFA 후보를 통해 검증망 접근 | 접근 경로 통제와 로깅이 명확 | 계정/단말 관리 필요 | 1순위 후보 |
| 허용 IP 목록 | 외주 고정 IP만 dev/staging 접근 허용 | 단순하고 빠름 | IP 변경, 공유망, 우회 리스크 | 2순위 후보 |
| Zero Trust Access | 사용자, 단말, MFA, 정책 기반 앱 접근 | 세밀한 정책과 세션 로그 | 상용 도구/정책 설계 필요 | 1~2순위 후보 |
| 임시 터널 | 단기 검수 URL을 만료 시간과 접근 정책으로 제공 | 빠른 임시 검수 | URL 유출, 로그/차단 체계 부족 가능 | 긴급/단기 후보 |
| Bastion/Jump Access | 제한된 관리 경유지에서만 접근 | 서버 접근 통제에 유리 | 운영 복잡도 증가 | 개발자/운영자 후보 |
| 공개 IP 직접 개방 | 서버/로컬 포트 직접 노출 | 설정이 쉬움 | 보안 사고 위험 큼 | 비권고, PM/A7/A9 승인 전 금지 |

결정: 우선 후보는 VPN 또는 Zero Trust이며, 허용 IP 목록은 보조 통제로 둔다. 임시 터널은 단기 검수에만 허용 후보로 둔다.

인당 생산성/마진 기여: 접속 속도와 보안 통제를 균형 있게 선택해 외주 검수 대기와 사고 리스크를 동시에 줄인다.

PM 승인 필요: 최종 접속 방식, 상용 도구, MFA 적용 방식, 임시 터널 사용 허용 범위.

## 6. 외주 접속 요청 입력

| 입력 | 필수 여부 | 설명 |
|---|---|---|
| `vendor_company` | 필수 | 외주 업체명 |
| `vendor_user_name` | 필수 | 외주 담당자 이름 |
| `vendor_user_email` | 필수 | 외주 담당자 이메일 |
| `vendor_contact` | 필수 | 비상 연락처 |
| `access_purpose` | 필수 | 접속 목적 |
| `target_environment` | 필수 | dev 또는 staging |
| `requested_start_at` | 필수 | 접속 시작 시각 |
| `requested_expires_at` | 필수 | 접속 만료 시각 |
| `allowed_source_ip` | 조건부 | 외주 고정 IP 후보 |
| `access_method_candidate` | 필수 | VPN, allowlist, Zero Trust, temporary tunnel 등 |
| `required_menu_ids` | 필수 | 필요한 메뉴 ID 목록 |
| `required_roles` | 필수 | 필요한 권한 목록 |
| `data_scope` | 필수 | 샘플/마스킹/비식별 데이터 범위 |
| `download_required` | 필수 | 다운로드 필요 여부, 기본값 false |
| `approver` | 필수 | PM 또는 위임 승인자 |

인당 생산성/마진 기여: 요청 입력을 표준화해 승인 왕복과 과다 권한 부여를 줄인다.

## 7. 접속 승인 산출물

| 산출물 | 설명 |
|---|---|
| 외주 접속 승인 기록 | 요청자, 승인자, 목적, 기간, 환경, 권한, 데이터 범위 |
| 외주 개인 계정 | 공유 계정 금지, 만료일 필수 |
| 접속 정책 | 접속 방식, 허용 IP, MFA 후보, 세션 제한 |
| 메뉴 권한 정책 | 접근 가능한 `menu_id`, `menu_name`, `route_id`, `actor_role` |
| 다운로드 정책 | 기본 차단, 예외 승인 시 범위/건수/목적 기록 |
| 접속로그 정책 | 로그인, 실패, 메뉴 진입, 조회, 변경, 차단, 다운로드 시도 |
| 회수 기록 | 계정 비활성, 허용 IP 제거, 터널 폐기, 세션 종료 |

인당 생산성/마진 기여: 승인과 회수 기록을 남겨 계약 종료 후 방치 계정 점검 시간을 줄인다.

## 8. 계정 수명주기

| 단계 | 요구사항 |
|---|---|
| 생성 | 개인별 계정만 허용하고 공유 계정은 금지한다. |
| 승인 | PM 승인, A7 보안 검토, A9 접속 환경 검토 후 활성화한다. |
| 권한 부여 | dev/staging, 메뉴, 기능, 데이터 범위 기준으로 최소권한 부여한다. |
| 만료 | `expires_at` 필수, 기본 만료 기간은 PM 승인 필요. |
| 연장 | 기존 권한 자동 연장 금지, 사유와 승인 재확인 필요. |
| 회수 | 계약 종료, 목적 종료, 이상 징후, 기간 만료 시 즉시 비활성화한다. |
| 검토 | 주기적으로 활성 외주 계정, 허용 IP, 터널, 세션을 점검한다. |

결정: 외주 계정은 생성 시점부터 만료와 회수를 기본값으로 둔다.

인당 생산성/마진 기여: 방치 계정을 줄여 보안 점검과 사고 대응 비용을 낮춘다.

PM 승인 필요: 기본 계정 만료 기간, 연장 승인권자, MFA 필수 여부.

## 9. 권한 및 데이터 통제

| 항목 | 기준 |
|---|---|
| 메뉴 접근 | 승인된 `menu_id`와 `route_id`만 허용한다. |
| 역할 | 외주 전용 역할 또는 제한된 `VendorReviewer` 후보 권한을 둔다. |
| 운영 데이터 | 운영 데이터 직접 조회 금지. |
| 개인정보 | 원칙적으로 비노출, 필요 시 마스킹 또는 샘플 데이터로 대체. |
| 다운로드 | CSV, Excel, API export, 첨부 다운로드 기본 차단. |
| 변경 권한 | 검수 목적이면 조회 중심 권한을 기본으로 하고 생성/수정/삭제는 별도 승인. |
| 시크릿 | 외주 계정과 접속 환경에 운영 시크릿 제공 금지. |
| 외부 연동 | 운영 결제/정산/배송 실연동 호출 금지, sandbox 또는 mock 후보 사용. |

결정: 외주 접속은 조회 중심, 다운로드 차단, 운영 데이터 차단을 기본 정책으로 둔다.

인당 생산성/마진 기여: 검수에 필요한 접근만 제공해 외주 협업 속도를 유지하면서 데이터 유출과 재처리 비용을 줄인다.

PM 승인 필요: 외주 전용 역할명, 생성/수정 권한 허용 범위, 다운로드 예외 승인 기준.

## 10. 접속로그와 메뉴별 로그 연계

### 10.1 필수 접속 로그 필드

| 필드 | 설명 |
|---|---|
| `vendor_company` | 외주 업체 |
| `vendor_user_email` | 외주 사용자 |
| `actor_user_id` | 시스템 사용자 ID |
| `actor_role` | 외주 권한 또는 역할 |
| `environment` | dev, staging |
| `access_method` | vpn, ip_allowlist, zero_trust, temporary_tunnel 등 |
| `source_ip` | 접속 원천 IP |
| `session_id` | 세션 ID |
| `event_time` | 이벤트 시각 |
| `action` | login, logout, menu_opened, list_viewed, detail_viewed, updated, export_requested, permission_denied 등 |
| `result` | success, failure, denied, expired, revoked |
| `reason_code` | 실패/차단/반출 사유 |
| `trace_id` | 시스템 추적 ID |

### 10.2 메뉴별 로그 필드

| 필드 | 설명 |
|---|---|
| `menu_id` | 메뉴 식별자 |
| `menu_name` | 메뉴 표시명 |
| `route_id` | 화면 또는 라우트 식별자 |
| `object_type` | 대상 객체 유형 |
| `object_id` | 대상 객체 ID |
| `pii_accessed` | 개인정보 접근 여부 |
| `download_attempted` | 다운로드 시도 여부 |

필수 이벤트:

- `login_success`
- `login_failure`
- `session_expired`
- `account_revoked`
- `menu_opened`
- `list_viewed`
- `detail_viewed`
- `created`
- `updated`
- `deleted`
- `export_requested`
- `permission_denied`
- `download_blocked`
- `data_access_blocked`

결정: 외주 접속로그는 메뉴별 로그와 같은 `actor_user_id`, `actor_role`, `menu_id`, `route_id`, `trace_id`로 연결한다.

인당 생산성/마진 기여: 외주 작업 경로와 화면 단위 행위를 연결해 장애 조사, 검수 이력 확인, 외감 대응 시간을 줄인다.

PM 승인 필요: 로그 보존기간, 개인정보 마스킹 방식, 외주 접속로그 조회 가능 권한.

인당 생산성/마진 기여: 외주 접근량과 차단 이벤트를 수치화해 불필요한 권한, 교육 필요, 위험 접속을 빠르게 식별한다.

## 12. 알림 후보

| 알림 | 조건 | 우선순위 |
|---|---|---|
| `Vendor Prod Access Attempt` | 외주 계정의 prod 접근 시도 | P1 |
| `Vendor PII Access Attempt` | 개인정보 또는 운영 데이터 접근 시도 | P1 |
| `Vendor Download Attempt` | 다운로드/반출 시도 | P2 |
| `Vendor Login Failure Spike` | 로그인 실패 급증 | P2 |
| `Vendor Permission Denied Spike` | 메뉴/기능 권한 차단 급증 | P3 |
| `Vendor Account Expiring` | 만료 예정 계정 존재 | P4 |
| `Vendor Account Expired But Active` | 만료 후 활성 계정 발견 | P1 |
| `Temporary Tunnel Expired But Reachable` | 만료된 임시 터널 접근 가능 상태 감지 | P1 |

결정: 운영 데이터 접근, 개인정보 접근, 만료 후 활성 상태는 높은 우선순위 알림으로 둔다.

인당 생산성/마진 기여: 외주 접속 리스크를 조기에 차단해 보안 사고와 운영 장애 대응 비용을 줄인다.

PM 승인 필요: 알림 채널, 온콜 대상, 임계값, 상용 보안관제 도구.

## 13. 다운로드/운영 데이터 차단

| 시나리오 | 기본 정책 | 로그 |
|---|---|---|
| CSV/Excel 반출 | 차단 | `export_requested`, `result=denied` |
| API export | 차단 | `export_requested`, `result=denied` |
| 첨부 파일 다운로드 | 차단 | `download_blocked` |
| 운영 데이터 조회 | 차단 | `data_access_blocked` |
| 개인정보 상세 조회 | 차단 또는 마스킹 | `permission_denied` 또는 `detail_viewed`, `pii_accessed=true` |
| 운영 시크릿 조회 | 차단 | `permission_denied` |

결정: 외주 계정의 다운로드와 운영 데이터 접근은 기본 차단하고 예외는 별도 승인 및 로그 반출 통제로 처리한다.

인당 생산성/마진 기여: 데이터 유출로 인한 손실과 외감/ISMS 대응 비용을 예방한다.

PM 승인 필요: 다운로드 예외 승인권자, 예외 반출 허용 범위, 반출 보존기간.
