# 결재 라인 스펙 초안

## 1. 목적

견적, 계약, 세금계산서/거래명세표 발행, 매출인식 조정, 입사등록 등 주요 업무에 대해 로그인 사용자를 상신자로 자동 지정하고 임의 결재 라인을 구성할 수 있게 한다.

인당 생산성/마진 기여: 결재 대기와 승인 누락을 줄이고 책임소재와 변경 이력을 자동으로 남긴다.

## 2. 입력

- 로그인 사용자 `employee_account_id`
- 결재 대상 유형
- 결재 대상 ID
- 결재자 목록
- 결재 순서
- 결재 사유

인당 생산성/마진 기여: 결재 입력을 표준화해 담당자가 문건마다 수기로 승인 경로를 설명하는 시간을 줄인다.

## 3. 출력

- 결재 문건
- 결재 라인
- 결재 상태
- 승인/반려 이력
- 타임로그/감사로그

인당 생산성/마진 기여: 결재 상태를 업무 진행과 연결해 매출 지연과 발행 지연 원인을 추적한다.

## 4. 핵심 규칙

- 문건 작성자는 현재 로그인한 임직원으로 자동 지정한다.
- 상신자는 결재라인에 필요한 임직원을 임의 배치할 수 있다.
- 결재 순서는 변경 가능하나 변경 이력을 남긴다.
- 최종 결재권자 지정이 가능해야 한다.
- 승인 완료 전 고위험 업무는 확정 처리하지 않는다.
- 입사등록은 단순히 `승인상태`로 표시하는 것이 아니라 결재문건을 상신하고 결재라인의 최종 승인 완료 후에만 입사 승인 완료로 반영한다.
- 승인, 반려, 보류, 결재 버튼은 각각 어떤 대상과 상태를 변경하는지 화면에 명확히 표시한다.
- 결재 버튼을 누른 뒤에는 현재 결재 상태, 현재 결재자, 다음 결재자, 반려/보류 사유를 즉시 확인할 수 있어야 한다.

인당 생산성/마진 기여: 시스템이 결재 흐름을 강제해 누락과 사후 확인 비용을 줄인다.

## 5. 인수조건

1. 로그인한 사용자가 결재 문건의 상신자로 자동 저장되어야 한다.
2. 임직원 목록에서 결재자를 추가하고 순서를 변경할 수 있어야 한다.
3. 결재라인 변경은 타임로그와 감사로그에 남아야 한다.
4. 승인, 반려, 회수 상태가 명확히 구분되어야 한다.
5. 권한 없는 사용자는 타인의 결재 문건을 수정할 수 없어야 한다.
6. 사용자가 승인/반려/보류 버튼을 누르기 전 해당 버튼의 처리 대상과 결과 상태를 알 수 있어야 한다.
7. 결재 버튼 클릭 후 결재 상태가 목록, 상세, 결재 타임라인 중 최소 한 곳에 즉시 반영되어야 한다.
8. 입사등록 승인상태는 연결된 결재문건의 현재 결재 상태와 일치해야 한다.
9. 입사등록 최종 승인 전에는 임직원 계정 활성화 또는 입사 확정 처리를 하지 않아야 한다.

인당 생산성/마진 기여: 결재 처리 기준을 고정해 승인 대기와 재작업을 줄인다.

## 6. PM 승인 항목

1. 결재 대상 업무 범위를 견적, 계약, 발행, 매출인식 조정, 입사등록으로 우선 제한해도 되는가?
2. 최종 결재권자 지정 규칙을 임의 배치로 시작하고 조직도 연동은 후속으로 미뤄도 되는가?
3. 결재 문건의 보존기간과 외감 증적 범위를 별도 승인으로 둘 것인가?
