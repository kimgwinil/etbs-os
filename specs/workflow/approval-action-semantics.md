# 결재 버튼 및 상태 표시 스펙 초안

## 1. 목적

승인, 반려, 보류, 결재 버튼이 각각 어떤 업무 상태를 변경하는지 명확히 하고, 결재 버튼을 누른 후 결재 상태를 즉시 확인할 수 있도록 한다.

인당 생산성/마진 기여: 버튼 의미 혼동으로 인한 오처리, 재상신, 승인 지연을 줄여 매출/발행/계약 처리 속도를 높인다.

## 2. 버튼 정의

| 버튼 | 의미 | 결과 상태 | 필수 입력 | 로그 |
|---|---|---|---|---|
| 결재 | 결재 문건을 열거나 결재 처리 화면으로 이동 | 상태 변경 없음 또는 결재 처리 화면 진입 | 없음 | 조회 로그 후보 |
| 승인 | 현재 결재자가 문건을 승인 | `approved` 또는 다음 결재자 대기 | 승인 의견 선택 | 타임로그/감사로그 |
| 반려 | 현재 결재자가 문건을 반려 | `rejected` | 반려 사유 필수 | 타임로그/감사로그 |
| 보류 | 현재 결재자가 추가 확인을 위해 처리를 보류 | `on_hold` | 보류 사유 필수 | 타임로그/감사로그 |
| 회수 | 상신자가 승인 전 문건을 회수 | `withdrawn` | 회수 사유 후보 | 타임로그/감사로그 |

인당 생산성/마진 기여: 버튼별 결과 상태를 고정해 사용자가 잘못된 버튼을 눌러 생기는 재작업을 줄인다.

## 3. 결재 상태 표시

결재 버튼 클릭 후 사용자는 다음 정보를 즉시 확인해야 한다.

- 현재 결재 상태
- 상신자
- 현재 결재자
- 다음 결재자
- 최종 결재권자
- 승인/반려/보류 이력
- 반려/보류 사유
- 결재 완료 여부
- 결재 대상 업무: 견적, 계약, 발행, 매출인식 조정 등
- 입사등록 결재인 경우 입사등록 대상자, 상신자, 현재 승인 단계, 최종 승인 후 반영될 입사 상태

인당 생산성/마진 기여: 결재 병목 위치를 즉시 보여줘 담당자가 누구에게 확인해야 하는지 빠르게 판단한다.

## 4. 화면 요구사항

- 목록에는 결재 상태 배지를 표시한다.
- 상세에는 결재 타임라인을 표시한다.
- 승인/반려/보류 버튼 근처에는 처리 결과 설명을 표시한다.
- 반려/보류는 사유 입력 없이는 처리할 수 없다.
- 승인 후 다음 결재자가 있으면 다음 결재자 대기 상태를 표시한다.
- 최종 승인 후 원 업무 상태가 어떻게 바뀌는지 표시한다.

인당 생산성/마진 기여: 결재 결과가 업무 상태에 미치는 영향을 화면에서 보여줘 후속 업무 대기 시간을 줄인다.

## 5. 업무별 결재 영향

| 대상 업무 | 최종 승인 시 반영 | 반려 시 반영 | 보류 시 반영 |
|---|---|---|---|
| 견적 | 견적 승인 완료, 계약 전환 가능 | 견적 수정 필요 | 견적 검토 대기 |
| 계약 | 계약 승인 완료, 주문 등록 가능 | 계약 수정 필요 | 계약 검토 대기 |
| 세금계산서/거래명세표 | 발행 진행 가능 | 발행 요청 반려 | 발행 보류 |
| 매출인식 조정 | 매출 조정 반영 가능 | 조정 요청 반려 | 조정 검토 대기 |
| 입사등록 | 입사 승인 완료, 임직원 계정 활성화 후보 | 입사등록 반려, 수정 필요 | 입사등록 검토 대기 |

인당 생산성/마진 기여: 결재 결과가 후속 업무 가능 여부와 연결되어 매출 지연과 발행 지연을 줄인다.

## 6. 인수조건

1. 승인, 반려, 보류, 결재 버튼의 의미가 화면에서 구분되어야 한다.
2. 반려와 보류는 사유 없이 처리되지 않아야 한다.
3. 결재 버튼 클릭 시 현재 결재 상태와 결재 타임라인을 확인할 수 있어야 한다.
4. 최종 승인 후 대상 업무의 다음 가능 상태가 표시되어야 한다.
5. 승인/반려/보류 처리는 타임로그와 감사로그에 남아야 한다.
6. 권한 없는 사용자는 승인/반려/보류 버튼을 사용할 수 없어야 한다.
7. 입사등록의 `승인상태`는 결재문건 상태와 분리 표시되지 않고 동일한 상태 체계로 확인되어야 한다.

인당 생산성/마진 기여: 결재 오처리와 상태 확인 문의를 줄여 승인 처리량을 높인다.
