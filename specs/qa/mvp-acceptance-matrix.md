# MVP 인수조건 검증 매트릭스

## 1. 목적

이 매트릭스는 이제너두 전사 CRM OS MVP의 P0/P1 모듈과 핵심 플로우를 QA 관점에서 인수 또는 반려하기 위한 기준표다. 모든 항목은 운영자 처리량, 오류 감소, 회귀 자동화 가능성, 보안/감사 대응성을 기준으로 검증한다.

인당 생산성/마진 기여: 인수조건을 KPI와 직접 연결해 기능 완성이 아니라 운영비 절감 가능성을 기준으로 릴리즈를 판단한다.

## 2. 공통 인수 필드

모든 MVP 스토리는 다음 필드를 포함해야 한다.

| 필드 | 필수 내용 | 누락 시 판단 |
|---|---|---|
| 목적 | 어떤 운영 병목 또는 리스크를 줄이는지 | 반려 |
| 입력 | 사용자 입력, 시스템 이벤트, 외부 연동 입력, 데이터 전제 | 반려 |
| 출력 | 화면 결과, API 응답, 데이터 변경, 로그, 큐 결과 | 반려 |
| 인수조건 | 정상/예외/권한/감사 기준 | 반려 |
| 의존성 | 선행 모듈, 데이터, 연동, 승인 항목 | 조건부 반려 |
| 담당 | 검증 담당과 수정 담당 | 반려 |
| KPI 영향 | 처리량, 오류율, 시간, 문의, 마진 관련 영향 | 반려 |

인당 생산성/마진 기여: 필수 필드 누락을 반려해 개발 완료 후 운영 가치 검증을 다시 하는 낭비를 줄인다.

## 6. 자동화 우선순위

| 우선순위 | 자동화 대상 | 이유 | 최소 커버리지 | 릴리즈 차단 조건 |
|---|---|---|---|---|
| 1 | 포인트 원장/잔액 API | 잔액 오류는 문의와 정산 오류로 직접 연결됨 | 지급, 차감, 취소, 복원, 만료, 멱등성 | 원장/잔액 불일치, 중복 변동 |
| 2 | 정산 배치/대사 API | 월마감과 외감 증적에 직접 영향 | 배치 생성, 재실행, 취소/환불, 예외 큐 | 금액 불일치, 중복 정산 |
| 3 | 심사 상태 전이 E2E/API | 운영자 처리량과 반려 품질에 직접 영향 | 접수, 배정, 승인, 보류, 반려 | 상태 이력 누락, 근거 없는 반려 |
| 4 | CS 티켓 E2E/API | 중복 문의와 SLA 초과를 줄임 | 접수, 배정, 이관, SLA, 완료 | 기준 데이터 미연결, SLA 누락 |
| 5 | 권한/테넌트 격리 | 모든 플로우의 기본 리스크 | 역할별 조회/변경, 타 테넌트 접근 차단 | 권한 우회, 개인정보 노출 |
| 6 | 연동 실패 주입 | 장애 대응 시간을 줄임 | timeout, 5xx, 중복 요청, 재시도, 보정 | 실패 유실, 중복 반영 |

인당 생산성/마진 기여: 자동화 순서를 오류 비용이 큰 업무부터 배치해 테스트 투자 대비 운영 절감 효과를 높인다.

| CS 데이터 | 고객사 문의, 임직원 문의, 공급사 문의, 중복 후보 | SLA, 이관, 활동 이력 검증 | 개인정보 포함 여부를 테스트 태그로 분리 |
| 연동 실패 데이터 | timeout, 4xx, 5xx, 중복 callback, malformed payload | 재시도와 수동 보정 검증 | 외부 API 상세 부재 시 mock으로 시작 |

인당 생산성/마진 기여: 테스트 데이터를 운영 예외 중심으로 구성해 실제 투입 시간이 큰 케이스를 먼저 줄인다.

## 8. 승인 보류 항목

| 항목 | 현재 판단 | QA 처리 |
|---|---|---|
| 개인정보 처리범위 | 가정 단계 | PM 김권일 승인 전 실제 항목 확정 금지 |
| 외부 연동 API 상세 | 가정 단계 | mock 기반 실패 테스트 후 A6 스펙 수신 시 갱신 |
| 정산 세금/수수료/반올림 기준 | 가정 단계 | 재무 기준 승인 전 금액 인수조건 조건부 표시 |
| 자동심사 자동 승인 범위 | 가정 단계 | MVP는 추천/분류/사람 검토 큐 기준으로 검증 |
| 운영 SLA | 가정 단계 | 임시 SLA로 테스트하되 릴리즈 전 운영 승인 필요 |

인당 생산성/마진 기여: 승인 보류 항목을 QA 매트릭스에서 분리해 미확정 리스크가 개발 범위를 부풀리지 않게 한다.
