# 임직원-거래처 담당 배정 스펙 초안

## 1. 목적

임직원 한 명이 여러 거래처를 담당할 수 있고, 거래처 화면에서 담당자를 명확히 확인할 수 있도록 임직원-거래처 다대다 배정 구조를 정의한다.

인당 생산성/마진 기여: 한 직원이 여러 거래처를 관리하는 현실을 반영해 인력 활용도를 높이고 담당자 공백과 중복 문의를 줄인다.

## 2. 입력

- 임직원 ID
- 거래처 ID
- 담당 역할: 주담당, 부담당, 승인담당, 참조담당 등
- 대표 담당자 여부
- 배정 시작일
- 배정 종료일
- 배정 사유

인당 생산성/마진 기여: 담당 배정 정보를 표준화해 거래처별 책임자를 빠르게 찾고 인수인계 시간을 줄인다.

## 3. 출력

- 임직원별 담당 거래처 목록
- 거래처별 담당자 목록
- 대표 담당자 표시
- 담당 역할 표시
- 배정 이력 및 변경 로그

인당 생산성/마진 기여: 거래처 화면에서 담당자를 즉시 확인해 업무 배정, 문의 응대, 승인 요청 시간을 줄인다.

## 4. 핵심 규칙

- 임직원 한 명은 여러 거래처에 배정될 수 있다.
- 거래처 하나는 여러 임직원을 담당자로 가질 수 있다.
- 거래처에는 대표 담당자 1명을 지정할 수 있다.
- 대표 담당자 외에도 부담당, 승인담당, 참조담당을 지정할 수 있다.
- 담당자 배정, 변경, 종료는 타임로그 대상이다.
- 권한 없는 사용자는 담당자 배정을 변경할 수 없다.

인당 생산성/마진 기여: 담당 구조를 다대다로 설계해 영업/운영 조직의 실제 업무 분담을 반영하고 처리 병목을 줄인다.

## 5. 화면 요구사항

- 임직원 관리 화면에서 담당 거래처를 여러 개 선택할 수 있어야 한다.
- 거래처 상세 화면에서 현재 담당자 목록이 보여야 한다.
- 거래처 목록에서 대표 담당자를 표시해야 한다.
- 담당자 선택 시 검색, 다중 선택, 역할 지정이 가능해야 한다.
- 담당자 변경 시 저장 전 변경 내용을 확인할 수 있어야 한다.

인당 생산성/마진 기여: 배정 화면에서 거래처와 담당자를 한 번에 확인해 관리자의 수작업 매칭 시간을 줄인다.

## 6. 데이터 모델

| 엔티티 | 설명 |
|---|---|
| `employee_account` | 임직원 |
| `customer_account` | 거래처 |
| `employee_customer_assignment` | 임직원과 거래처의 담당 배정 관계 |

`employee_customer_assignment` 주요 필드:

- `assignment_id`
- `employee_account_id`
- `customer_account_id`
- `assignment_role`
- `is_primary`
- `effective_from`
- `effective_to`
- `assignment_status`
- `assigned_by`
- `created_at`
- `updated_at`

인당 생산성/마진 기여: 1:1 관계를 없애고 배정 테이블로 관리해 조직 변경과 거래처 확대에도 데이터 재구성을 줄인다.

## 7. 인수조건

1. 임직원 한 명에게 거래처 여러 개를 배정할 수 있어야 한다.
2. 거래처 하나에 담당자 여러 명을 배정할 수 있어야 한다.
3. 거래처 상세 화면에서 담당자 목록과 대표 담당자를 확인할 수 있어야 한다.
4. 임직원 상세 화면에서 담당 거래처 목록을 확인할 수 있어야 한다.
5. 담당자 배정 변경은 타임로그에 남아야 한다.
6. 권한 없는 사용자는 담당자 배정을 변경할 수 없어야 한다.

인당 생산성/마진 기여: 인수조건을 다대다 배정과 가시성 중심으로 잡아 담당자 누락에 따른 업무 지연을 줄인다.
