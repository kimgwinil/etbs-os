# 타임로그/감사로그 및 로그기록 메뉴 스펙 초안

## 1. 목적

고객정보, 임직원정보, 매출정보, 상품정보 등 핵심 정보의 변경과 조회 이력을 남기고, 설정 메뉴 내 별도 로그기록 확인 메뉴에서 조회할 수 있게 한다.

인당 생산성/마진 기여: 문제 원인 추적과 외감 대응 자료 수집 시간을 줄인다.

## 3. 출력

| 출력 | 설명 |
|---|---|
| 로그 대상 매트릭스 | 고객정보, 임직원정보, 매출정보, 상품정보, 결재라인, 발행, 매출인식, 산식 변경 이벤트 |
| 필수 로그 필드 | 타임로그/감사로그/접근로그 공통 필드와 대상별 연결 키 |
| 설정 메뉴 로그기록 요구 | 필터, 정렬, 상세 조회, 권한별 접근 범위 |
| 권한별 접근 범위 | 일반, 관리자, 슈퍼바이저, 경영자 로그 조회 기준 |
| 담당 배정 로그 요구 | 임직원-거래처 배정 변경 권한, 담당자 노출, 변경 타임로그 기준 |
| 결재 버튼 로그 요구 | 승인/반려/보류 사유, 권한 없는 결재 버튼 차단, 보류 상태 감사 증적 기준 |
| 입사등록 로그 요구 | 승인 전 계정 활성화/권한 부여 차단, 입사등록 처리범위 승인 게이트 |
| 메뉴별 로그 요구 | 메뉴 진입/조회/수정/결재/반출 로그, 개인정보 마스킹, 보존·접근권한 |
| 수익성 비용 입력 로그 요구 | 비용 입력 권한 부여/회수, 변경 전후 값, 권한 없는 접근 차단 로그 |
| 외주 접속 로그 요구 | 외주 개인별 계정, 만료일, 접속 방식, 메뉴별 로그, 다운로드 차단, 회수 이력 |
| 팀 채팅 로그 요구 | 채팅방 생성, 참여자 추가, 메시지 전송, 파일 첨부, 외부/권한 없는 초대 차단 |
| PM 승인 필요 항목 | 3개 이하 승인 범주 |

인당 생산성/마진 기여: 로그 산출물을 화면, API, QA가 동시에 재사용해 중복 설계를 줄인다.

인당 생산성/마진 기여: 로그 대상을 명확히 해 누락 증적으로 인한 조사 지연을 줄인다.

## 6. 로그기록 확인 메뉴

- 설정 메뉴 하위에 `로그기록` 메뉴를 둔다.
- 기간, 사용자, 대상 엔티티, 이벤트 유형, 권한, 고객/상품/주문 기준으로 필터링한다.
- 권한에 따라 조회 가능한 로그 범위를 제한한다.
- 개인정보 포함 로그는 마스킹 또는 제한 조회를 기본으로 한다.
- 타임로그, 감사로그, 개인정보 접근로그를 탭 또는 필터로 구분한다.
- 로그 목록은 발생시각, 이벤트 유형, 대상, 사용자 기준 정렬을 지원한다.
- 로그 상세는 변경 전후 참조, 승인 ID, 관련 업무 ID, 발행 문서 ID, 산식 버전, 배정 ID, 결재 버튼 의미를 보여준다.
- 로그 목록 조회, 상세 조회, 반출 요청 자체도 로그로 남긴다.
- 담당 배정 로그는 임직원, 거래처, 담당 역할, 대표 담당자 여부, 변경 사유 기준으로 필터링할 수 있어야 한다.
- 결재 로그는 결재, 승인, 반려, 보류, 회수, 권한 차단 이벤트와 사유 기준으로 필터링할 수 있어야 한다.
- 메뉴별 로그는 메뉴명, 라우트, 이벤트 유형, 사용자, 권한, 기간 기준으로 필터링할 수 있어야 한다.
- 입사등록 로그는 입사등록 ID, 대상 임직원, 결재문건 ID, 결재 상태, 상신자, 현재 결재자 기준으로 필터링할 수 있어야 한다.
- 수익성 비용 입력 로그는 제원원가, 판관비, 일반관리비, 산식 버전, 입력자, 적용일 기준으로 필터링할 수 있어야 한다.
- 비용 입력 권한 로그는 권한 부여/회수, 대상 임직원, 부여자/회수자, 승인 ID 기준으로 필터링할 수 있어야 한다.
- 메뉴별 로그의 개인정보 포함 값과 검색 조건은 기본 마스킹하고, 마스킹 해제 또는 반출은 승인 ID와 접근로그를 요구한다.
- 외주 접속 로그는 외주 업체, 개인별 계정, 접속 방식, 허용 IP/정책, 만료일, 메뉴 ID, 다운로드 시도, 권한 차단 기준으로 필터링할 수 있어야 한다.
- 팀 채팅 로그는 채팅방 유형, 참여자, 메시지, 첨부파일, 콘텐츠 위험 분류, 외부/권한 없는 초대 차단 기준으로 필터링할 수 있어야 한다.

인당 생산성/마진 기여: 필요한 로그를 빠르게 찾게 해 운영/재무/보안 담당자의 조사 시간을 줄인다.

## 7. 권한별 접근 범위

| 권한 | 로그기록 메뉴 접근 | 허용 범위 | 제한 |
|---|---|---|---|
| 일반 | 제한 허용 | 본인이 생성/처리한 영업활동, 파이프라인, 견적, 주문, 결재 타임로그 | 전사 로그, 타 임직원정보, 영업이익 산식 변경 로그 접근 제한 |
| 관리자 | 허용 | 담당 팀 또는 업무 범위의 고객정보, 상품정보, 주문, 출고, 발행, 담당 배정 로그 | 권한 변경, 산식 변경, 전사 개인정보 로그 접근 제한 |
| 슈퍼바이저 | 허용 | 전사 업무 로그, 이익 저하 원인 로그, 산식 적용 로그 후보, 담당 배정 집계 후보 | 개인정보/임직원정보 상세와 담당자 개인정보는 승인된 범위만 접근 |
| 경영자 | 제한 허용 | 전사 KPI와 외감 제출용 집계/증적 후보 | 개인정보/임직원정보 상세, 권한 변경, 산식 변경 불가 |
| 보안/개인정보 담당 | 허용 | 개인정보 접근로그, 권한 변경, 로그 조회 이력 | 업무 데이터 변경 불가 |
| 재무/감사 담당 | 허용 | 발행, 매출인식, 산식 변경, 정산/외감 증적 | 개인정보 상세 접근 제한 |
| 외주 계정 | 제한 허용 | 승인된 `dev`/`staging` 메뉴의 본인 활동 로그 후보 | 운영 환경, 개인정보 원문, 운영 데이터, 다운로드/반출, 전사 로그 접근 제한 |
| 채팅 참여자 | 제한 허용 | 본인이 참여한 채팅방의 메시지/파일 메타데이터와 제한적 활동 로그 | 참여자 외 채팅방, 외부 초대, 민감정보 파일 다운로드, 전사 채팅 로그 접근 제한 |

인당 생산성/마진 기여: 권한별 조회 범위를 명확히 해 필요한 사람은 빠르게 찾고 불필요한 민감정보 노출은 줄인다.

## 8. 로그기록 메뉴 필터/정렬 인수조건

| ID | 요구사항 | 인수조건 |
|---|---|---|
| `LOGVIEW-01` | 기간 필터 | 기본 조회는 최근 기간으로 제한하고 무제한 전체 조회를 허용하지 않는다. |
| `LOGVIEW-02` | 사용자/권한 필터 | 행위자, 권한, 팀, 담당자 기준 필터가 가능해야 한다. |
| `LOGVIEW-03` | 대상 필터 | 고객, 임직원, 매출, 상품, 주문, 발행, 결재, 담당 배정, 산식 버전 기준으로 조회 가능해야 한다. |
| `LOGVIEW-04` | 이벤트 필터 | 생성, 수정, 삭제, 조회, 결재, 승인, 반려, 보류, 회수, 발행, 취소, 조정, 산식 변경, 권한 차단으로 구분한다. |
| `LOGVIEW-05` | 개인정보 마스킹 | 개인정보 포함 로그는 기본 마스킹하고 상세 원문은 승인 ID를 요구한다. |
| `LOGVIEW-06` | 상세 조회 기록 | 로그 상세 조회와 반출 요청 자체가 감사로그로 남아야 한다. |
| `LOGVIEW-07` | 담당 배정 필터 | 임직원, 거래처, 담당 역할, 대표 담당자 여부, 유효기간 기준으로 배정 변경 로그를 조회할 수 있어야 한다. |
| `LOGVIEW-08` | 결재 상태 필터 | 승인, 반려, 보류, 회수, 권한 차단, 현재 결재자 기준으로 결재 로그를 조회할 수 있어야 한다. |
| `LOGVIEW-09` | 메뉴별 로그 필터 | 메뉴명, 라우트, 이벤트 유형, 사용자, 권한 기준으로 메뉴별 로그를 조회할 수 있어야 한다. |
| `LOGVIEW-10` | 입사등록 결재 로그 필터 | 입사등록, 상신, 승인, 반려, 보류, 최종 승인 반영 로그를 결재문건과 연결해 조회할 수 있어야 한다. |
| `LOGVIEW-11` | 수익성 비용 입력 로그 필터 | 제원원가, 판관비, 일반관리비 입력/수정/삭제 로그를 입력자, 권한, 적용일, 산식 버전 기준으로 조회할 수 있어야 한다. |
| `LOGVIEW-12` | 외주 접속 로그 필터 | 외주 업체, 개인별 계정, 접속 방식, 허용 IP/정책, 만료일, 메뉴, 다운로드 시도, 권한 차단 기준으로 조회할 수 있어야 한다. |
| `LOGVIEW-13` | 팀 채팅 로그 필터 | 채팅방, 방 유형, 참여자, 메시지, 첨부파일, 콘텐츠 위험 분류, 외부/권한 없는 초대 차단 기준으로 조회할 수 있어야 한다. |

인당 생산성/마진 기여: 필터와 정렬 기준을 고정해 대량 로그에서 필요한 증적을 찾는 시간을 줄인다.

## 9. 인수조건

1. 핵심 정보 생성/수정/삭제 시 타임로그가 남아야 한다.
2. 개인정보/권한/매출인식/산식 변경은 감사로그 대상이어야 한다.
3. 설정 메뉴에서 로그기록 확인 메뉴가 제공되어야 한다.
4. 로그 목록은 정렬과 필터를 지원해야 한다.
5. 권한 없는 사용자는 로그 상세를 볼 수 없어야 한다.
6. 고객정보, 임직원정보, 매출정보, 상품정보는 대상별 필수 연결 키로 재조회 가능해야 한다.
7. 결재라인, 발행, 매출인식, 영업이익 산식 변경은 변경 전후 참조와 승인 ID를 가져야 한다.
8. 슈퍼바이저/경영자/관리자/일반 권한별 로그 조회 범위가 테스트 가능해야 한다.
9. 로그기록 메뉴의 목록 조회, 상세 조회, 반출 요청도 로그로 남아야 한다.
10. 임직원-거래처 담당 배정 생성, 역할 변경, 대표 담당자 변경, 종료는 `assignment_id` 기준 타임로그로 남아야 한다.
11. 권한 없는 담당 배정 변경과 권한 없는 승인/반려/보류 버튼 실행은 서버에서 차단되고 `result=denied` 로그로 남아야 한다.
12. 반려와 보류는 사유 없이 처리되지 않아야 하며, 보류 상태는 보류 사유, 보류자, 시작시각, 재개 또는 최종 처리 이력으로 조회 가능해야 한다.
13. 설정 메뉴의 로그기록 화면에서 메뉴별 로그를 확인할 수 있어야 한다.
14. 입사등록 승인상태 변경은 연결된 결재문건과 결재라인 로그를 통해 추적 가능해야 한다.
15. 입사등록 최종 승인 전 계정 활성화와 권한 부여 시도는 차단되고 `result=denied` 로그로 남아야 한다.
16. 메뉴 진입, 조회, 수정, 결재, 반출 로그는 메뉴 ID와 라우트 ID를 포함하고 개인정보 포함 값은 기본 마스킹되어야 한다.
17. 제원원가, 판관비, 일반관리비 입력/수정/삭제는 마스터 또는 입력 권한자만 가능하며 변경 전후 값과 산식 버전이 감사로그에 남아야 한다.
18. 비용 입력 권한 부여/회수와 권한 없는 비용 입력 접근은 감사로그에 남아야 한다.
19. 외주 접속은 개인별 계정, 만료일, 접속 방식, 메뉴별 로그를 가져야 하며 다운로드/반출과 개인정보/운영 데이터 접근은 기본 차단되어야 한다.
20. 공개 IP 직접 개방은 비권고이며 PM/A7/A9 명시 승인 없는 외부 접속 활성화 시도는 차단 로그로 남아야 한다.
21. 팀 채팅방 생성, 참여자 추가/제거, 메시지 전송, 파일 첨부, 다운로드 시도는 감사로그 또는 타임로그로 남아야 한다.
22. 외부 사용자 또는 권한 없는 사용자 초대는 차단되고 `result=denied` 로그로 남아야 한다.
23. 개인정보·민감정보 포함 가능 메시지와 파일은 콘텐츠 위험 분류, 마스킹 여부, 다운로드 권한, 보존기간 후보를 기록해야 한다.

인당 생산성/마진 기여: 로그 조회 화면까지 인수조건에 포함해 “로그는 남지만 못 찾는” 문제를 방지한다.

## 10. 담당

- 주 담당: A7
- 협업: A3, A8, A9

인당 생산성/마진 기여: 담당을 분리해 로그 정책, 화면, 검증, 보존 운영을 병렬로 보강한다.
