# 메뉴별 로그기록 스펙 초안

## 1. 목적

설정 메뉴의 `로그기록`에서 메뉴별 로그를 확인할 수 있도록 메뉴 진입, 조회, 생성, 수정, 삭제, 결재, 반출, 필터 저장 등의 행위를 메뉴 단위로 기록한다.

인당 생산성/마진 기여: 어떤 메뉴에서 어떤 사용자가 어떤 작업을 했는지 빠르게 추적해 장애 조사, 권한 점검, 외감 대응 시간을 줄인다.

## 2. 입력

- 메뉴 ID
- 메뉴명
- 라우트 ID
- 사용자 ID
- 사용자 권한
- 대상 엔티티
- 이벤트 유형
- 이벤트 결과
- 사유 코드

인당 생산성/마진 기여: 메뉴 단위 로그 입력을 표준화해 로그 검색과 분석을 자동화 후보로 만든다.

## 3. 출력

- 메뉴별 로그 목록
- 메뉴별 사용자 활동 이력
- 메뉴별 생성/수정/삭제/조회/결재/반출 집계
- 권한 없는 접근 시도 목록
- 로그 상세

인당 생산성/마진 기여: 메뉴별 사용량과 오류/차단 이벤트를 확인해 교육, 권한 정비, 화면 개선 우선순위를 정할 수 있다.

## 4. 기록 대상 이벤트

| 이벤트 | 설명 |
|---|---|
| `menu_opened` | 메뉴 진입 |
| `list_viewed` | 목록 조회 |
| `detail_viewed` | 상세 조회 |
| `created` | 신규 생성 |
| `updated` | 수정 저장 |
| `deleted` | 삭제 또는 비활성 |
| `approved` | 승인 처리 |
| `rejected` | 반려 처리 |
| `on_hold` | 보류 처리 |
| `export_requested` | CSV/Excel/API 반출 요청 |
| `filter_saved` | 필터/보기 저장 |
| `permission_denied` | 권한 없는 접근 또는 실행 차단 |

인당 생산성/마진 기여: 메뉴별 이벤트를 표준화해 반복 오류와 권한 이슈를 빠르게 찾는다.

## 5. 설정 메뉴 로그기록 화면

- 상단 메인 설정 메뉴 하위에 `로그기록` 메뉴를 둔다.
- 메뉴명, 기간, 사용자, 권한, 이벤트 유형, 결과, 대상 엔티티로 필터링한다.
- 메뉴별 로그 탭을 제공한다.
- 개인정보 포함 로그는 기본 마스킹한다.
- 로그 조회와 로그 상세 조회 자체도 로그로 남긴다.

인당 생산성/마진 기여: 메뉴별 로그를 설정에서 바로 확인하게 해 담당자가 개발자나 DB 조회에 의존하는 시간을 줄인다.

## 6. 인수조건

1. 각 주요 메뉴 진입 시 `menu_opened` 로그가 남아야 한다.
2. 목록/상세 조회, 생성, 수정, 삭제, 결재, 반출 이벤트가 메뉴 ID와 함께 기록되어야 한다.
3. 설정 메뉴의 로그기록에서 메뉴별 로그를 필터링해 볼 수 있어야 한다.
4. 권한 없는 메뉴 접근 또는 버튼 실행은 `permission_denied`로 기록되어야 한다.
5. 메뉴별 로그 상세 조회도 감사로그로 남아야 한다.

인당 생산성/마진 기여: 인수조건을 메뉴별 추적 가능성에 맞춰 운영/감사 대응 수작업을 줄인다.
