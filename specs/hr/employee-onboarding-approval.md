# 입사등록 결재 승인 스펙 초안

## 1. 목적

입사등록 화면의 `승인상태`를 단순 표시값이 아니라 결재라인을 통한 실제 결재 상태로 정의한다. 입사등록은 결재문건 상신, 결재라인 설정, 승인/반려/보류 처리, 최종 승인 반영까지 연결되어야 한다.

인당 생산성/마진 기여: 입사 승인 기준을 결재라인으로 표준화해 임직원 계정 활성화 오류, 승인 누락, 권한 오부여로 인한 재작업을 줄인다.

## 2. 입력

- 입사등록 대상자 정보 후보
- 입사 예정일
- 소속/부서 후보
- 직무/권한 후보
- 상신자: 현재 로그인 사용자
- 결재라인: 결재자 목록, 결재 순서, 최종 결재권자
- 상신 사유

인당 생산성/마진 기여: 입사등록에 필요한 입력과 결재 입력을 분리해 HR/관리자가 승인 누락 없이 처리할 수 있게 한다.

## 3. 출력

- 입사등록 문건
- 연결된 결재문건
- 결재라인
- 현재 승인상태
- 승인/반려/보류 이력
- 최종 승인 후 임직원 계정 활성화 후보
- 타임로그/감사로그

인당 생산성/마진 기여: 입사등록 상태와 결재 상태를 한 화면에서 확인해 승인 확인 문의와 계정 활성화 지연을 줄인다.

## 4. 상태 정의

| 상태 | 의미 | 다음 가능 상태 |
|---|---|---|
| `draft` | 입사등록 초안 | `submitted`, `withdrawn` |
| `submitted` | 결재 상신 완료 | `in_review`, `withdrawn` |
| `in_review` | 결재 진행 중 | `approved`, `rejected`, `on_hold` |
| `on_hold` | 추가 확인으로 보류 | `in_review`, `rejected`, `withdrawn` |
| `rejected` | 반려 | `draft` 또는 종료 |
| `approved` | 최종 결재 승인 | `employee_activation_pending` |
| `employee_activation_pending` | 계정 활성화 대기 | `activated` |
| `activated` | 입사등록 최종 반영 | 종료 |

인당 생산성/마진 기여: 입사등록과 계정 활성화 사이에 승인 게이트를 둬 권한 오부여와 재처리를 줄인다.

## 5. 핵심 규칙

- 입사등록의 `승인상태`는 연결된 결재문건의 상태를 기준으로 표시한다.
- 입사등록 저장만으로 승인 완료가 되지 않는다.
- 결재라인이 없으면 결재 상신을 할 수 없다.
- 최종 결재권자 승인 전에는 임직원 계정 활성화 또는 권한 부여를 완료하지 않는다.
- 반려와 보류는 사유 입력이 필수다.
- 결재라인 변경, 승인, 반려, 보류, 최종 승인 반영은 타임로그/감사로그 대상이다.

인당 생산성/마진 기여: 입사등록 처리 기준을 강제해 승인 없는 계정 생성과 권한 오류를 줄인다.

## 6. 화면 요구사항

- 입사등록 상세에 `결재상태` 배지를 표시한다.
- `결재` 버튼을 누르면 결재 타임라인, 현재 결재자, 다음 결재자, 최종 결재권자를 보여준다.
- 결재라인 설정 화면에서 임직원을 추가/순서변경/삭제할 수 있어야 한다.
- 승인/반려/보류 버튼의 의미와 결과 상태를 버튼 주변에 명확히 표시한다.
- 최종 승인 후 어떤 정보가 임직원 정보로 반영되는지 미리 보여준다.

인당 생산성/마진 기여: 결재 진행 상태를 즉시 보여줘 승인 대기 위치와 다음 조치를 빠르게 판단하게 한다.

## 7. 인수조건

1. 입사등록의 승인상태는 결재문건 상태와 일치해야 한다.
2. 결재라인 설정 전에는 상신이 차단되어야 한다.
3. 최종 결재 승인 전에는 계정 활성화가 완료되지 않아야 한다.
4. 반려/보류는 사유 없이 처리되지 않아야 한다.
5. 결재 버튼 클릭 시 현재 상태, 현재 결재자, 다음 결재자, 최종 결재권자를 확인할 수 있어야 한다.
6. 입사등록 생성, 수정, 상신, 승인, 반려, 보류, 활성화는 타임로그/감사로그에 남아야 한다.

인당 생산성/마진 기여: 입사등록 인수조건을 결재와 계정 활성화 기준으로 묶어 HR 처리 오류를 줄인다.
